# Глоссарий терминов НаПаре

Единый источник терминологии. Все документы ссылаются на этот файл.

---

## Основные понятия

| Термин | Определение |
|--------|-------------|
| **НаПаре** | Операционная система учебного дня студента. Название продукта. |
| **Пара** (Lesson) | Конкретное занятие в расписании. Центральная сущность системы. Привязана к группе, преподавателю, аудитории, времени. |
| **Пространство пары** (PairSpace) | Страница контекста конкретной пары: объявления, подготовка, файлы, обсуждение и связанные данные. Срок доступности сверяйте с backend-моделью и политикой retention. |
| **Мой день** | Главный экран студента. Персональная сводка: пары, изменения, дедлайны, новые материалы. Собирается без AI. |
| **Коннектор** (Connector) | Модуль получения расписания из внешнего источника (парсер сайта, Excel/CSV, iCal). Имеет единый интерфейс `ScheduleConnector`. |
| **LessonChange** | Запись об изменении пары (отмена, перенос, смена аудитории, смена преподавателя); обработка change event может сформировать in-app notification. |

## Пользователи и роли

| Термин | Код роли | Описание |
|--------|----------|----------|
| **Студент** | `student` | Основной пользователь. Видит своё расписание, пространства пар, ставит статус отсутствия. |
| **Преподаватель** | `teacher` | Публикует контент в пространства пар (объявления, ДЗ, файлы). |
| **Куратор** | `curator` | Роль для разрешённых backend действий сопровождения и посещаемости. |
| **Декан факультета** | `faculty_dean` | Управление факультетом, просмотр аналитики по факультету. |
| **Зав. кафедрой** | `department_head` | Управление кафедрой, расписание кафедры. |
| **Админ вуза** | `university_admin` | Управление структурой вуза, ролями, расписанием. Проректор / IT-отдел. |
| **Суперадмин** | `superadmin` | Управление платформой. Подключение вузов, коннекторы, общая аналитика. |
| **Разработчик** | `developer` | Роль платформы. Фактические разрешения задаются backend-кодом; роль сама по себе не подтверждает доступ к конкретному окружению. |

В текущей модели `User` хранит одну роль (`UserRole`). Не предполагайте одновременное назначение нескольких ролей без изменения модели и API.

## Сущности данных

| Термин | Описание |
|--------|----------|
| **University** | Учебное заведение. Ключ мультивузовости. |
| **Faculty** | Факультет / институт в рамках вуза. |
| **Group** | Учебная группа. Привязана к факультету. |
| **Teacher** | Привязка преподавателя к вузу и кафедре. |
| **Lesson** | Пара в расписании. Привязана к группе, преподавателю, аудитории, времени, неделе. |
| **PairSpace** | Пространство пары. Одно на каждую Lesson. |
| **Announcement** | Объявление преподавателя в пространстве пары. |
| **Homework** | Домашнее задание в пространстве пары. |
| **HomeworkSubmission** | Legacy запись отправки работы, сохранённая в схеме; не считать текущим UX или интеграцией с Moodle без соответствующего endpoint. |
| **HomeworkProgress** | Статус подготовки по заданию, если он включён соответствующим маршрутом; это не workflow проверки/оценки преподавателем. |
| **FileAttachment** | Файл, загруженный в пространство пары. |
| **DiscussionMessage** | Сообщение в обсуждении пары. |
| **AbsenceStatus** | Статус отсутствия студента (болен, работа и т.д.). |
| **AbsenceConfirmation** | Подтверждение/отклонение статуса куратором. |
| **Notification** | Запись уведомления для интерфейса; системная push-доставка отдельно не реализована. |
| **DeviceToken** | Сохранённый токен устройства; наличие токена не означает реализованную отправку push. |
| **AuditLog** | Запись аудита только для событий, которые явно создаёт текущий код. |

## Статусы отсутствий

| Статус | Код | Цвет |
|--------|-----|------|
| Учусь | `learning` | зелёный |
| Болен | `sick` | оранжевый/красный |
| Работа / занятость | `work` | синий |
| Другой город | `other_city` | фиолетовый |
| Другая причина | `other` | серый |

## Метрики

| Термин | Определение |
|--------|-------------|
| **DAU** | Daily Active Users — уникальные пользователи за день. |
| **WAU** | Weekly Active Users — уникальные пользователи за неделю. |
| **MAU** | Monthly Active Users — уникальные пользователи за месяц. |
| **Retention D1/D7/D30** | Доля вернувшихся пользователей через 1/7/30 дней. |
| **NPS** | Net Promoter Score — индекс лояльности (-100 до +100). |
| **PMF** | Product-Market Fit — подтверждение ценности продукта. |
| **CAC** | Customer Acquisition Cost — стоимость привлечения клиента. |
| **LTV** | Lifetime Value — пожизненная ценность клиента. |
| **Student+** | Платная подписка для студентов (после MVP). |

## Технические термины

| Термин | Определение |
|--------|-------------|
| **JWT** | JSON Web Token; фактические сроки и claims задаются конфигурацией и backend-кодом. |
| **OpenAPI** | Спецификация API, создаваемая NestJS Swagger из кода; snapshot следует получать из работающего API. |
| **university_id** | UUID вуза на соответствующих доменных записях. Tenant/resource scope проверяется backend-ом; поле есть не у каждой таблицы. |
| **PairSpace** | Пространство пары. |
| **LessonChange** | Запись об изменении расписания. |
| **NormalizedLesson** | Термин из проектного описания коннекторов; проверяйте фактические DTO/entities и адаптеры, прежде чем считать его runtime интерфейсом. |
| **Deep link** | Ссылка, открывающая конкретный экран в приложении. |
| **Push** | Системное push-уведомление. FCM/APNs доставка в текущем backend не подключена. |
| **In-app** | Уведомление внутри приложения (центр уведомлений). |
