# Привязка аккаунтов преподавателей СИБИТ к расписанию

Внешний ID преподавателя из rasp.sano.ru хранится в `users.sourceTeacherId`. При синхронизации он сопоставляется с этим значением, а ID аккаунта записывается в `lessons.teacherId`. Группа привязана к каждой записи занятия; преподавателю не назначается одна основная группа через `users.groupId`.

Каталог для администраторов: `/admin/users`. На карточке преподавателя можно выбрать запись из расписания. При создании преподавателя там же можно выбрать запись источника; имя инициалами подставится автоматически, а текущие пары синхронизируются после создания аккаунта. У одной записи источника может быть только один аккаунт в рамках университета.

`GET /api/v1/admin/sibit/teachers` (с токеном администратора университета) возвращает внешний ID, имя, число занятий, список групп и текущее состояние привязки. СИБИТ не публикует корпоративные email преподавателей и полные имена: для каждого аккаунта нужен реальный корпоративный email. Вакансию `Вакансия_26560 (каф.1)` не следует заводить как аккаунт.

## Пакетное создание на сервере

Сначала обновите приложение до версии с миграцией `1700000000023-SibitTeacherLinks`, затем синхронизируйте расписание СИБИТ на странице `/admin/schedule-import`. CLI использует актуальные строки импортированных занятий, проверяет ID преподавателя и повторные запуски не создают дубли.

Подготовьте защищённый JSON-манифест на сервере. В нём нужны внешний ID и корпоративная почта; ФИО и группы берутся из последней синхронизации:

```json
[
  { "sourceTeacherId": "20", "email": "teacher@example.org" },
  { "sourceTeacherId": "32", "email": "another.teacher@example.org" }
]
```

Скопируйте его в backend-контейнер, сначала выполните просмотр, затем примените:

```bash
BACKEND_CID=$(docker compose -f docker-compose.prod.yml ps -q backend)
docker cp /secure/path/sibit-teachers.json "$BACKEND_CID:/tmp/sibit-teachers.json"

docker compose -f docker-compose.prod.yml exec backend \
  node dist/cli/provision-sibit-teachers.js \
  --university-id "UUID_УНИВЕРСИТЕТА" \
  --input /tmp/sibit-teachers.json \
  --dry-run

docker compose -f docker-compose.prod.yml exec backend \
  node dist/cli/provision-sibit-teachers.js \
  --university-id "UUID_УНИВЕРСИТЕТА" \
  --input /tmp/sibit-teachers.json \
  --apply \
  --credentials-output /tmp/sibit-teacher-credentials.json

docker cp "$BACKEND_CID:/tmp/sibit-teacher-credentials.json" /secure/path/sibit-teacher-credentials.json
chmod 600 /secure/path/sibit-teacher-credentials.json
```

Новые аккаунты получают случайные временные пароли. CLI пишет их только в файл с правами владельца, не в терминал. Передайте файл преподавателям защищённым способом и удалите его после доставки. Уже существующий аккаунт можно привязать по email, если это активный аккаунт преподавателя того же университета; пароль при этом не меняется. Расписание уроков связывается с каждым аккаунтом по внешнему ID, а список групп выводится из назначенных ему занятий.

Внешние данные расписания могут обновиться между подготовкой манифеста и запуском CLI; тогда предварительный просмотр покажет фактические занятия и группы из последней синхронизации. Пропущенная/неизвестная группа или преподаватель остановит выполнение до изменения базы.
