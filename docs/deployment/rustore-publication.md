## Обязательные шаги до отправки

1. Дополнить публичный email поддержки и адрес для обращений. Оформить действующую политику обработки данных от имени указанного ИП: категории, цели, получатели, сроки, удаление и контакты. Старый `docs/legal/privacy_policy.md` — черновик с несовпадающими с реализацией формулировками; не публиковать его без сверки. На момент проверки `https://napare.sano.ru/privacy` возвращает 404. Разместить политику по этому URL, проверить 200 без входа и доступ из «О приложении». Также подготовить правила пользования, если применимы требования к UGC.
2. Доработать удаление/обезличивание аккаунта и путь внутри приложения. Сейчас DELETE `/api/v1/users/me` лишь выставляет isActive=false, имя/email и связанные записи сохраняются. Это нельзя объявлять готовым удалением по п. 5.4 RuStore. Согласовать с оператором и вузом состав и сроки хранения учебных данных; не удалять ведомости и историю посещаемости произвольно. Запрос только по email не заменяет требуемый путь в приложении.
3. Проверить APK на Android-телефоне или эмуляторе: установка поверх предыдущей версии без потери локальных записей; вход/выход каждой заявленной роли; поворот, клавиатура, «Назад», выбор файлов, календарь; офлайн-план после полного закрытия и открытия; изменение/удаление/отправка записей и очистка всех записей. На текущем компьютере `adb devices` не обнаружил устройство, эмулятор не установлен. Сборка и JVM-тесты не являются доказательством работы Android UI.
4. Получить не менее 3 настоящих скриншотов из APK на телефоне, например расписание тестовой группы, заполненный план и подготовка. Использовать только вымышленные данные. Не заменять их браузерными снимками, чужими экранами или макетами. Рекомендованный рабочий размер — 1080×1920, PNG/JPG, до 3 МБ на файл. Руководство RuStore указывает минимум 3 скриншота на выбранный тип устройства.
5. Подготовить магазинную иконку 512×512 PNG/JPG до 3 МБ с непрозрачным фоном по всей площади. Исходный launcher-знак имеет прозрачный фон и другое разрешение; файл `source-logo.png` в пакете — исходник для оформления, не готовая иконка RuStore. Разместите существующий знак на сплошном фоне в графическом редакторе, экспортируйте 512×512. Исходный бренд/логотип в репозитории при подготовке не менялся.
6. Создать аккаунт для модерации по инструкции ниже. Проверить все указанные в описании функции на опубликованном сайте: APK использует production, локальные изменения кабинетов сами собой на сервер не попадут.
7. Заполнить возрастную классификацию по реальному содержимому, подтверждения прав на бренд и учебные материалы, раздел безопасности данных. Не присваивать автоматически 0+ и не заявлять отсутствие обработки данных только потому, что Android запрашивает лишь INTERNET.

## Аккаунт для модерации

Создайте отдельное тестовое учебное заведение/контур с вымышленными преподавателями, группой и занятиями на актуальную неделю. Через платформенную панель владельца/уполномоченного DevOps создайте активного пользователя student с отдельным email и случайным паролем не менее 12 символов, привяжите к тестовому вузу. Через администратора этого вуза назначьте тестовую группу и заполните демонстрационное расписание, подготовку и уведомления. Не использовать реальную группу, реальные персональные данные, роль developer/superadmin или аккаунт владельца.

На production эти действия ещё не выполнены, тестовые данные не создавались. Новая платформенная панель должна быть сначала развёрнута; если она ещё не установлена, используйте штатную административную панель вуза. Войдите данным аккаунтом из чистой установки APK и подтвердите доступность всех заявленных сценариев. При наличии разных закрытых сценариев дайте проверяющим отдельные минимальные роли/инструкции, не повышая студента до администратора. Логин, пароль и период тестового расписания передайте только в поле комментария модератору в RuStore, не в публичном описании и не в Git. Сохраните доступ действующим на период проверки; после завершения отзовите сессии/смените пароль при необходимости.

## Действия в RuStore Консоли

1. Откройте [RuStore Консоль](https://console.rustore.ru/), войдите с VK ID и создайте аккаунт «Юридическое лицо или ИП». Укажите реквизиты своего ИП. Пройдите подтверждение тем способом, который предлагает консоль. Официальная инструкция описывает подписание регистрационной формы квалифицированной электронной подписью и настройку КриптоПро; используйте актуальный предложенный сценарий, если он отличается.
2. После доступа к кабинету добавьте приложение Android. Загрузите `NaPare-1.1.0.apk`. Для этой небольшой Java/WebView-сборки достаточно подписанного APK; AAB и загрузка приватного ключа для AAB не требуются. Не передавайте keystore в RuStore при обычной загрузке APK.
3. Убедитесь, что package name — `ru.napare.app`, versionCode — 2. При следующем релизе увеличьте versionCode; сохраняйте один и тот же сертификат подписи для обновления существующего приложения.
4. Заполните название «НаПаре» (до 30 знаков), краткое описание (до 80), полное описание (до 4000), категорию «Образование», фактический возрастной рейтинг и контакты. Название должно быть доступно/уникально в магазине. Добавьте проверенную публичную ссылку на политику.
5. Заполните безопасность данных: учётная запись/имя/email, учебные данные, причины отсутствий и документы при использовании этих функций, загружаемые пользователем материалы, технические журналы и подключённые сторонние сервисы — только в объёме фактической production-реализации. Android INTERNET используется для связи с napare.sano.ru. Камера, микрофон, геолокация, контакты и широкое чтение файлов приложению не нужны; выбор документов осуществляется системным диалогом. Локальный план не отправляется на сервер автоматически, но пользователь может сам поделиться его содержимым через Android.
6. Загрузите готовую иконку и минимум 3 скриншота. Добавьте «Что нового?» и приватный комментарий с тестовым доступом. Не заявляйте нативный push, полное офлайн-расписание, поддержку ТВ или функции, ещё не развёрнутые на сайте.
7. Выберите ручную публикацию после одобрения, проверьте карточку и отправьте версию на модерацию только после устранения блокеров выше. Загрузка/отправка/публикация в этой подготовке не выполнялись.
8. При отклонении исправляйте указанную причину в том же приложении. При изменении APK увеличьте versionCode, соберите с прежней подписью и отправьте новую версию. Не создавайте копию под другим package name для обхода отказа.
9. После одобрения опубликуйте вручную, установите приложение именно из RuStore, проверьте обновление, вход и основные сценарии. Сохраните ссылку карточки и следите за отзывами/сбоем сайта.

## Сборка и материалы

```powershell
./scripts/build-android.ps1 -AndroidSdk 'C:/Android/Sdk' -JavaHome 'C:/Program Files/Java/jdk-17' -SigningConfigPath 'C:/private/release.private.json' -PreviousApkPath 'C:/private/previous-release.apk'
```

Скрипт запускает assembleRelease, lintRelease и testReleaseUnitTest, проверяет подпись и её совпадение с предыдущим APK, получает версию из APK и пишет build-result.json без секретов. APK и JSON остаются вне Git. Приватный ключ и пароль храните отдельно с защищённой резервной копией: их потеря может лишить возможности обновлять приложение.
