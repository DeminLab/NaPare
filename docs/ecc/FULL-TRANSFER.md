# Полный снимок ECC и интеграция Codex

NaPare использует закреплённый ECC 2.2.3. Установка сохраняет все 4 878 файлов релиза в локальном ZIP и проверяет каждый Git blob. Компоненты, доступные как точки входа Codex, собираются отдельно. Источник и версия заданы в [манифесте](../../scripts/ai-devkit/skill-adapters/ecc/sources.json). Лицензия MIT присутствует в архиве и в [копии проекта](../../scripts/ai-devkit/skill-adapters/ecc/upstream/LICENSE).

## Установка

Из корня NaPare укажите локальный Git-репозиторий с закреплённым коммитом. Если такого репозитория нет, получить только нужный коммит можно командами ниже.

```powershell
$eccSource = Join-Path $env:TEMP ('napare-ecc-' + [guid]::NewGuid())
git init $eccSource
git -C $eccSource fetch --depth=1 https://github.com/affaan-m/ECC.git 3f14a103a8694e51c1df9a806217a6d0b5f7a6f7
py scripts/ai-devkit/install-ecc.py --source-repo $eccSource
py scripts/ai-devkit/install-ecc.py --check
```

На Linux используйте `python3`. Для совместного запуска с установщиком DevKit передайте `-EccSourceRepo $eccSource` скрипту [install.ps1](../../scripts/ai-devkit/install.ps1). Установка ECC проверяет существующие файлы, сохраняет несовпадающие и повторно использует идентичные. Она читает Git и пишет только в проект NaPare. Для подхвата нового каталога откройте новую сессию Codex из корня доверенного проекта.

## Использование

| Что | Как открыть в Codex |
| --- | --- |
| Общий каталог | Вызовите `$ecc-catalog`. Поиск по компонентам ведётся в `.cache/ai-devkit/ecc/catalog.json` |
| 323 Skills | Вызывайте явно, например `$ecc-typescript-patterns`. Каждый адаптер указывает закреплённый источник и работает в границах NaPare |
| 98 команд | Вызывайте как Skills `$ecc-command-<имя>`. Например, `$ecc-command-plan`. Команды Claude записаны в каталоге по исходным именам |
| 72 профиля | Поручите узкую задачу агенту `ecc-<имя>` в клиенте с поддержкой именованных ролей. Для трёх отдельных Codex-ролей ECC каталог указывает соответствия в NaPare |
| Правила и контексты | Откройте поле `reference` нужной записи в каталоге, например `.cache/ai-devkit/ecc/references/contexts/review.md`. Применяйте правила к соответствующим файлам и стеку |
| MCP и hooks | Каталог показывает эквиваленты NaPare и компоненты с отдельными требованиями к доступу, среде или runtime. Состояния в каталоге описывают способ переноса, а не результат подключения |

Манифест [проектного marketplace](../../.agents/plugins/marketplace.json) позволяет клиенту показать ECC в каталоге плагинов. В проверенном Codex 0.146.0 проектный флаг сам по себе не заполнил пользовательский кэш плагина. Точки входа загружаются из нативных папок проекта. Остальные рабочие пространства и настройки Claude не требуют изменений.

Папки Skills и профилей, созданные установщиком, игнорируются Git. В репозитории хранятся проектный манифест, входной Skill, закреплённая версия и установщик. Повторите установку для каждого свежего клона. Codex читает готовые Markdown-файлы из проектного кэша, поэтому вызову Skill не нужен интерпретатор Python.

## Границы переноса

- Архив содержит все файлы закреплённого релиза. Проектные Skills ссылаются на инструкции из него по требованию. Четыре специализированных сценария остаются в исходном архиве. Для проверок безопасности NaPare используйте существующий `napare-security`.
- Chrome DevTools, Context7, Playwright и GitHub используют конфигурацию NaPare. Файловые операции, локальная техническая память и планирование используют эквиваленты проекта или клиента. 31 запись MCP остаётся справочной и требует проверки зависимостей, доступа или обращения с данными. Внешние сервисы автоматически не запускаются.
- Используются существующие проектные `SessionStart` и процесс технической памяти. Остальные профили hooks, сборщики наблюдений и ECC2 доступны как исходники. Их нативный запуск в Codex не подтверждён. Общий workflow ревью сопоставлен с `napare-code-review` и `ecc-command-orch-review`.
- Проверки CLI, проектного каталога и неизвестные границы перечислены в [отчёте](VERIFICATION.md#расширение-р2р5-поставка-и-проверки).

## Откат

Команда `py scripts/ai-devkit/install-ecc.py --remove` сначала сверяет сохранённые хеши, затем удаляет только созданные установщиком файлы и кэш. Изменённый файл блокирует автоматическое удаление. Для удаления записи из каталога плагинов адресно верните добавленные строки проектного TOML и запись ECC в marketplace. Ранее существующие Skills, профили, MCP и настройки Claude в этот откат не входят.
