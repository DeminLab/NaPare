# Исходные требования к интеграции ECC

Зафиксировано 19 ноября 2026 года по заданию пользователя. Изменения требований вносить только по явной команде пользователя. Технические решения и результаты вести в отдельных документах.

Репозиторий ECC: [affaan-m/ECC](https://github.com/affaan-m/ECC.git).

> Твоя задача — интегрировать Everything Claude Code (ECC) в существующий проект NaPare и полностью адаптировать его под Codex.
>
> Работай строго поэтапно, с постоянным сохранением состояния задачи между сессиями.

## Этапы

1. Анализ ECC, NaPare и совместимости с Codex.
2. Установка совместимых компонентов ECC.
3. Создание и адаптация AGENTS.md.
4. Интеграция Skills под технологический стек NaPare.
5. Настройка специализированных агентов.
6. Подключение полезных MCP.
7. Адаптация Hooks и автоматических проверок.
8. Создание постоянной технической памяти проекта.
9. Оптимизация расходования контекста и лимитов Codex.
10. Комплексное тестирование интеграции.

## Обязательный протокол работы

Создай следующие файлы:

- `docs/ecc/REQUIREMENTS.md` — исходные требования.
- `docs/ecc/PLAN.md` — подробный план реализации с чек-листом.
- `docs/ecc/PROGRESS.md` — текущее состояние выполнения.
- `docs/ecc/DECISIONS.md` — принятые технические решения.
- `docs/ecc/VERIFICATION.md` — результаты фактических проверок.

Используй эти файлы как постоянный источник контекста.

Перед началом каждого этапа и после сжатия контекста перечитывай требования, план и текущий прогресс.

Добавь соответствующее правило в корневой AGENTS.md, сохранив существующие инструкции.

## Строгие ограничения

- Не отклоняйся от поставленной задачи.
- Не изменяй бизнес-логику NaPare.
- Не занимайся исправлением посторонних багов.
- Не меняй дизайн приложения.
- Не пропускай этапы.
- Не переписывай исходные требования под собственные решения.
- Не создавай неподдерживаемые конфигурации.
- Не устанавливай всё подряд: проверяй совместимость, безопасность и пользу каждого компонента.
- Не изменяй production-инфраструктуру.
- Не уничтожай существующие изменения разработчиков.
- Не выполняй автоматический push.
- Не используй платные сторонние API без разрешения.

Если обнаружишь постороннюю проблему, запиши её отдельно, но не переключайся на её исправление.

Если возникнет техническое ограничение, зафиксируй его и предложи совместимое решение, не скрывая проблему.

## Критерии завершения этапа

Этап считается завершённым только после выполнения всех его требований, проверки результата и обновления файлов прогресса.

Не отмечай непроверенную функциональность как рабочую.

После каждого этапа предоставляй краткий отчёт:

- Что сделано.
- Какие файлы изменены.
- Какие проверки выполнены.
- Какие проблемы обнаружены.
- Что осталось сделать.

После завершения этапа остановись и дождись команды на продолжение.
