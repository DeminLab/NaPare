# Прогресс интеграции ECC

Текущее состояние на 20 ноября 2026 года (Asia/Omsk). Десять этапов исходного плана завершены. По команде «переноси полностью сразу» расширение выполнено одним проходом. Полный снимок ECC и 493 созданные точки входа установлены в рабочей копии. Границы подключения и отдельные непроверенные сценарии записаны в [инструкции](FULL-TRANSFER.md) и [отчёте](VERIFICATION.md#расширение-р2р5-поставка-и-проверки).

Перед продолжением прочитать [REQUIREMENTS.md](REQUIREMENTS.md), [PLAN.md](PLAN.md) и этот файл. Для решений открыть [DECISIONS.md](DECISIONS.md), для подтверждений — [VERIFICATION.md](VERIFICATION.md).

## Журнал этапа 1

- Прочитаны источники NaPare и закреплён upstream ECC `2.2.3` по SHA `3f14a103a8694e51c1df9a806217a6d0b5f7a6f7`. Контекст NaPare сверялся с рабочим деревом. Конфигурация DevKit и проектные Skills уже существовали до этапа.
- Записана матрица переноса. Выбран проектный подход с двумя кандидатами для последующего полного просмотра. При старте этапа 2 исходники можно повторно получить по SHA. Временный каталог текущего анализа не нужен для возобновления.
- Изменены пять файлов в `docs/ecc/`, добавлены правило в [корневой AGENTS.md](../../AGENTS.md) и ссылка в [индекс документации](../README.md). Полная адаптация инструкций остаётся на этапе 3.
- Пройдены целевой и общий Markdownlint, проверка ссылок и состава документации, offline DevKit verifier, локальное чтение project config и обнаружение 20 профильных Skills. Проверены исходное содержание двух изменённых файлов и сохранность существующего рабочего дерева.
- На завершении этапа 1 установка ECC ещё не началась.

Коллизия, ошибочный хеш и повторный запуск проверены на изолированных файлах. В рабочем дереве повторный запуск сохранил содержимое и время изменения всех трёх файлов.

## Ограничения подтверждения

- Установлен полный снимок релиза и набор проектных точек входа. Отдельные runtime и внешние MCP имеют собственные условия подключения. Клиентские ограничения приведены в инструкции полного переноса.

- Установка справочных копий, применение Skills, четыре локальных MCP и изолированный `SessionStart` подтверждены в соответствующих проверках. В desktop выполнены проверки двух нативных профилей. Compaction проверен на локальной заглушке.
- Для Chrome DevTools используется существующий закреплённый launcher NaPare. Авторизованный CLI runtime GitHub, Figma и Sentry остаётся непроверенным. Проверка чтения GitHub относится к отдельному коннектору.
- Поддержка `agent_type` зависит от поверхности. Для проверенного CLI используется текстовое поручение, для проверенного desktop доступен нативный выбор. При смене клиента повторить проверку схемы и результата.

## Расширение. Журнал Р1

- Сверены закреплённое дерево ECC, нативный манифест, конфигурация Codex и пересечения с NaPare. Прямые коллизии: `design-system`, `code-reviewer` и Chrome DevTools. Манифест покрывает часть полного дистрибутива.
- Подготовлены этапы Р2–Р5 для поставки, переноса и приёмки полного дистрибутива. Инвентаризация и решение описаны в [VERIFICATION.md](VERIFICATION.md#расширение-р1-инвентаризация-полного-ecc) и [DECISIONS.md](DECISIONS.md#d15-проектная-поставка-полного-ecc).

## Расширение. Журнал Р2–Р5

- Установщик подготовил архив 4 878 файлов ECC и 695 записей каталога. Созданы 323 проектных Skills, 98 адаптеров команд и 72 TOML-профиля. Три Codex-роли сопоставлены с существующими. Профильные Skills NaPare сохранили видимость после перевода расширенного каталога на явный вызов.
- Проверены чистая установка, повтор, коллизия, хеши, чтение ссылочного файла и адресный откат. Marketplace обнаружен в app-server. В отдельном профиле подтверждены его регистрация и удаление. Рабочие точки входа доступны из проектных папок без регистрации marketplace в пользовательском профиле.
- MCP, hooks, техническая память и отдельный runtime учтены в каталоге. Используются подтверждённые интерфейсы DevKit. Для неподключённых компонентов указаны ограничения. [Инструкция](FULL-TRANSFER.md) и [отчёт](VERIFICATION.md#расширение-р2р5-поставка-и-проверки).
