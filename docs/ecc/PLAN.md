Последовательность и условия остановки заданы в [REQUIREMENTS.md](REQUIREMENTS.md). Текущий этап сверять по [PROGRESS.md](PROGRESS.md). Выбор компонентов обоснован в [DECISIONS.md](DECISIONS.md). Фактически выполненные проверки вести в [VERIFICATION.md](VERIFICATION.md).

## Протокол между этапами и сессиями

1. Перечитать требования, этот план и прогресс до начала этапа и после сжатия контекста. Сверить номер этапа с последней командой пользователя. При расхождении сохранить состояние и работать в пределах команды пользователя.
2. Снять состояние Git и проверить затрагиваемые пути. Для существующих файлов отделить исходный diff от изменений этапа. Перед настройкой сохранять только затрагиваемые конфиги и учитывать ранее существовавшие файлы.
3. Выполнить только чек-лист текущего этапа. По каждому компоненту записать происхождение, решение и проверку. Отдельно записать посторонние проблемы и ограничения среды.
4. Зафиксировать в прогрессе завершённые пункты, оставшиеся шаги, пути и команду для возобновления. При незавершённой проверке указать границу и повторяемый следующий шаг. После отчёта ожидать команды пользователя.

## Расширение. Полный ECC для Codex

20 ноября 2026 года пользователь уточнил новый объём: «весь ЕСС». Он охватывает нативный пакет и компоненты вне его манифеста. Исходные десять этапов сохраняются как история завершённой выборочной интеграции. По последующей команде «переноси полностью сразу» этапы расширения выполняются последовательно в одном проходе. Остальные ограничения NaPare применяются к расширению.

### Р1. Инвентаризация и выбор способа переноса

- [x] Сверить дерево закреплённого ECC, содержимое Codex-манифеста, отдельные наборы для Claude и альтернативные runtime.
- [x] Проверить проектный путь публикации в первичной документации Codex и обнаружить прямые пересечения с NaPare.
- [x] Зафиксировать состав, границы и контрольные проверки дальнейших этапов.

### Р2. Воспроизводимая проектная поставка

- [ ] Собрать проектный marketplace из проверенных файлов. Отдельно подтвердить, что CLI и desktop распознают проектную запись. Проверить чистый запуск, повтор и коллизию. Выявить условия, при которых клиенты сохраняют состояние за пределами проекта.

- [ ] Перенести совместимые Skills и роли в отдельное пространство имён при конфликте. Сохранить договорённости NaPare и проверить discovery. Команды, правила и workflows сопоставить с поддерживаемыми точками входа Codex и подтвердить вызов на синтетических задачах.
