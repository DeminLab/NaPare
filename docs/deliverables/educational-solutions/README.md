## Перед передачей проверяющим

1. Выкатить эту версию на публичный HTTPS-сервер и подключить сайт как Mini App URL в настройках одобренного MAX-бота.
2. Сгенерировать OpenAPI-файл из работающего NestJS Swagger, который является источником API-контракта:

   ```bash
   PUBLIC_APP_URL=https://your-public-domain.example bash scripts/export-case-openapi.sh
   ```

   Замените пример адресом опубликованного сайта/API. Команда сохранит `openapi.json` в `deliverables/educational-solutions/`; публичный HTTPS endpoint должен отдавать Swagger JSON по `/api/v1/docs-json`.
3. Зафиксировать и указать commit финального исходного кода.
4. Подготовить отдельную демо-БД и учётки по [сценарию демо](../../hackathon-demo.md). Сгенерированные пароли и bot token передавать только защищённо; в репозиторий их не добавлять.
5. На первом слайде новой презентации уже указаны MAX-бот и репозиторий, а на последнем — тестовые логины и пароли. После выкладки добавьте в копию для проверяющих публичный URL и commit hash именно развёрнутой версии. `MAX_BOT_TOKEN` передавайте только через окружение backend, не включайте его в презентацию.

[DATA-API.yaml](DATA-API.yaml) описывает обе привязки MAX (первый вход студента по университетским данным и связывание MAX преподавателя с активной сессией сайта), тестовые роли, проверку QR и ожидаемые ответы. Для этих двух ролей используйте разные тестовые аккаунты MAX. Перед передачей укажите в `base_url` фактический публичный API origin своей выкладки, без `/api/v1`. Расписание демо синтетическое и обозначается в интерфейсе/материалах; отметка создаётся API во время показа. `openapi.json` формируется с того же публичного адреса.

## Запуск локальных компонентов

В корне репозитория скопируйте `.env.example` в `.env`, замените шаблонные значения JWT, базы и Redis случайными секретами и задайте `MAX_BOT_TOKEN`. Затем поднимите локальные компоненты одной командой:

```powershell
docker compose --env-file .env -f docker-compose.prod.yml up -d --build
```

После запуска общая точка входа находится на `http://localhost:8080/`, документация API — на `http://localhost:8080/api/v1/docs`. Для остановки без удаления тестовых данных выполните `docker compose --env-file .env -f docker-compose.prod.yml down`.

Для реального запуска Mini App MAX нужен публичный HTTPS-сайт и bot token MAX. Локальный HTTP запуск сам по себе не является доступным MAX-ботом.
