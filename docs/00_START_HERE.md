# НаПаре — Документация проекта

**НаПаре** — операционная система учебного дня студента.  
B2B2C SaaS для вузов: расписание, задания, материалы, коммуникация и учёт отсутствий вокруг каждой пары.

**Пилотный контекст:** СИБИТ (Омск). Фактический статус пилота и доступность серверов определяйте по deployment environment; этот документ сам по себе их не подтверждает.

## Ключевые принципы

1. **Single Source of Truth** — каждый факт живёт в одном месте. Остальное только ссылается.
2. **AI-first** — рабочие документы сохраняйте короткими и адресными; исторический архив и API-контракт могут быть длиннее.
3. **Module-bounded** — детали backend-модулей находятся в `modules/` и рядом с кодом.
4. **Living docs** — OpenAPI строится из backend-кода; схему БД определяют TypeORM entities и миграции. Обновляйте документацию вместе с изменениями, не называйте вручную написанную заметку генератором.

## Термины

Все термины — в [02_GLOSSARY.md](02_GLOSSARY.md). Ключевые:

| Термин | Значение |
|--------|----------|
| **Пара** | Конкретное занятие (Lesson) — центральная сущность |
| **Пространство пары** | Страница пары со всем контентом (PairSpace) |
| **Мой день** | Главный экран студента — персональная сводка |
| **Коннектор** | Модуль получения расписания из внешнего источника |
| **university_id** | Идентификатор вуза на доменных записях, которым он нужен; tenant/resource scope проверяется backend-ом |

## Что НЕ редактировать

`archive/TZ_00_MASTER_TZ.md` — **старый полный документ**. Перенесён в архив.  
Рабочие документы — `modules/*`, `architecture/*`, `clients/*` и т.д. В каждом сначала проверьте отметку статуса: проектные эскизы и старые планы не равны текущей реализации.
