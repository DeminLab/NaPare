# Роли и границы доступа

Коды всех 11 ролей совпадают с `UserRole` в `apps/backend/src/auth/interfaces/user-role.ts`. Этот документ описывает смысл ролей; конкретное разрешение API задают controller decorators, guards и проверки сервисов. [Проверяемая матрица разрешений и входного контроля всех маршрутов](../security/role-matrix.md) фиксирует текущую реализацию.

## Роли

| Код | Название продукта | Назначение |
|---|---|---|
| `student` | Студент | Собственная группа, расписание, Pair Space, посещаемость и личные настройки |
| `employer` | Работодатель | Карьерные задачи и взаимодействие с кандидатами; проверки владения компанией выполняет карьерный сервис |
| `career_staff` | Сотрудник карьерного центра | Карьерные процессы своего вуза в рамках сервисных проверок |
| `career_admin` | Администратор карьерного центра | Управление карьерными процессами своего вуза в рамках сервисных проверок |
| `teacher` | Преподаватель | Назначенные занятия и учебные действия в пределах backend resource checks |
| `curator` | Прежняя основная роль куратора | Вход сохранён для совместимости; доступ к назначенным группам через дополнительные назначения, без права редактирования посещаемости |
| `faculty_dean` | Декан факультета | Действия в разрешённой области факультета, если конкретный endpoint их поддерживает |
| `department_head` | Заведующий кафедрой | Действия в разрешённой области кафедры, если конкретный endpoint их поддерживает |
| `university_admin` | Администратор ВУЗа | University cabinet и endpoints управления своим вузом |
| `superadmin` | Суперадминистратор | Явно ограниченные platform administration endpoints |
| `developer` | Разработчик | Технический кабинет; наличие роли не даёт автоматически доступ к учебным данным |

В текущей entity/API у пользователя одно значение `role`. Клиентская навигация помогает открыть нужную поверхность, но не заменяет backend authorization.

С 15 октября 2026 года в рабочей копии кураторство реализовано отдельными назначениями на существующие аккаунты студента/сотрудника. Основная роль и сессия не меняются. Назначения и снятия доступны деканату и администраторам своего университета; группы и кураторы связаны отношением многие-ко-многим. Подробные права, миграция и API: [кураторство на аккаунте](../product/account-curatorship.md). Это описание реализации, а не подтверждение её публикации.

## Клиентские поверхности

| Поверхность | Типичная роль | Доступ |
|---|---|---|
| Student workspace | `student` | Персональные данные и группа пользователя |
| Staff workspace | `teacher`, `curator` | Назначенные занятия/группы и разрешённые действия |
| University cabinet | `university_admin`, `faculty_dean`, `department_head` | Только функции, предоставленные отдельным endpoint и его проверками |
| Developer workspace | `developer` | Техническая документация и диагностика |

`superadmin` — административное разрешение, а не отдельная пользовательская поверхность.

## Где проверять разрешения

- Ролевой enum: `apps/backend/src/auth/interfaces/user-role.ts`.
- Route policy: `@Roles(...)` в соответствующем controller.
- Общие проверки: `apps/backend/src/common/guards/roles.guard.ts` и `university.guard.ts`.
- Ресурсные/tenant проверки: профильный service и соответствующие тесты.
- Сгенерированный API-контракт: `/api/v1/docs`.

PostgreSQL RLS policies отсутствуют. Tenant isolation выполняется приложением; проверяйте tenant + resource ownership в каждом новом endpoint. Не переносите матрицы из старых спецификаций как фактические ACL без сверки с текущим controller/service.

## Владелец и делегированное управление платформой

Полный доступ новой панели привязан к UUID владельца, назначенного офлайн. Ни developer, ни superadmin не становятся владельцами автоматически. Остальные получают явные разрешения и ограничения по сервисам; старые полномочия superadmin не отменяются. [Реализация](../product/platform-control.md).

Профиль DevOps включает все оперативные разрешения и сервисы, управление университетами и пользователями, в том числе другими техническими аккаунтами. Владелец сохраняет исключительное управление «Контуром доверия»: назначение полномочий и экстренный отзыв всех платформенных назначений с завершением технических сессий. Владельца нельзя заблокировать или сбросить ему пароль через делегированное управление аккаунтами.
