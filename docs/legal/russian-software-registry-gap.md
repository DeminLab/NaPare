# Реестр российского ПО: материалы и пробелы НаПаре

Дата: 22 октября 2026. Читатель: владелец/юрист/ответственный за заявку. Это инженерная сверка репозитория и подготовительный перечень, не решение о соответствии, не факт включения и не поданная заявка.

## Источники и предел проверки

Официальный [портал реестра](https://reestr.digital.gov.ru/?lang=ar) в индексируемой инструкции указывает подготовку документов, инструмента электронной подписи и ознакомление с Правилами/методическими рекомендациями. [Раздел документов](https://reestr.digital.gov.ru/documents/?PAGEN_5=19) перечисляет Правила ведения реестров. Прямое открытие страниц при проверке завершилось timeout; полный действующий текст требований получить не удалось. Значения порогов/особых условий и комплект формы на дату подачи **не подтверждены**; закрывать этот пункт плана как полную юридическую проверку нельзя.

Официальный [пример записи](https://reestr.digital.gov.ru/request/2047895/) показывает поля класса ПО, сайта документации, стоимости/открытой лицензии, оснований прав и выплат. Это пример заполнения другого продукта, не доказательство текущих требований или допуска НаПаре. Не переносить чужие реквизиты/основания/нулевые выплаты.

В колонке «проверить» указаны вопросы для актуальных Правил и формы. Наличие файла в Git не заменяет документ юридического лица.

## Пакет к сбору

Создать вне публичного Git защищённую папку заявки: документы заявителя/полномочий; доказательства исключительных прав; расчёт выплат с основаниями; заполненная карточка версии/класса; публичные документы функций/установки/эксплуатации/стоимости; описание жизненного цикла и поддержки; инструкция экспертного доступа и проверенный экземпляр; лицензии/состав компонентов и дополнительные документы по применимым условиям. Конкретные обязательные вложения сверить в рабочей форме и Правилах. В Git остаются только пустые шаблоны и технические материалы без персональных документов/подписей.

Перед подачей юрист фиксирует редакцию Правил, пункт каждого критерия, доказательство и ответственного; инженер проверяет чистую установку; бухгалтер подписывает расчёт. Затем заявитель отдельно подаёт и отслеживает запросы экспертов. Эти действия требуют реальных реквизитов и не выполнялись агентом. Пока критерии и документы не подтверждены, нельзя рекламировать «в реестре», обещать льготы/допуск к закупке или выбирать закупочный способ на этом основании.
