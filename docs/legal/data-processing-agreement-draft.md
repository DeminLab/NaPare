Версия 0.1 от 22 октября 2026. **Черновик для юриста и сторон. Не подписан, не оферта, не разрешение включать обработку.** Роли сторон должны быть определены по каждой цели. Если поставщик самостоятельно определяет цель, её нельзя автоматически включить в поручение вуза.

## Обязательные приложения

| Приложение | Что стороны обязаны заполнить до действия поручения |
| --- | --- |
| A. Цели и субъекты | Цель каждой операции, студенты/сотрудники/представители, несовершеннолетние, кто обеспечивает основание |
| B. Перечень данных и операций | Выбранные строки [карты](../privacy/data-map.md); сбор/запись/хранение/уточнение/передача/обезличивание/уничтожение, разрешённые действия и запреты |
| C. Основания и подтверждение | Документы оператора для каждого процесса; отдельный порядок здоровья, публичного распространения и представительства |
| D. Площадки и получатели | Основная БД, файлы, backup, логи, очереди, интеграции, поддержка; организация/страна/адрес, порядок изменения |
| E. Защита и контроль | Границы ИСПДн, утверждённые угрозы/уровень, меры, роли, логи, аудит, подтверждающие материалы без раскрытия секретов |
| F. Хранение и прекращение | Для каждого класса срок/начальное событие/основание исключения/способ уничтожения, backup и акт; дата прекращения договора |
| G. Сервис и контакты | Ответственные, защищённый канал, сроки уведомления/ответа, SLA/RPO/RTO по испытаниям, аварийная процедура |

## Проект условий исполнения

1. Обработчик действует только по документированным указаниям оператора и в согласованных целях. Запрещены использование учебных данных для собственной рекламы, обучение моделей, публичное раскрытие и передача неуказанным получателям.
2. Оператор определяет законное основание, необходимый объём и срок каждой цели. Обработчик содействует подтверждению исполнения и сообщает о противоречивом/невыполнимом указании до его исполнения.
3. Доступ получают назначенные сотрудники по минимально необходимым правам. Технический аккаунт не получает автоматического межвузовского доступа; временные разрешения ограничены scope и журналируются. Обязанность конфиденциальности сохраняется после прекращения доступа.
4. Новая площадка, субподрядчик, внешний API или расширение состава передаваемых данных включаются только после согласованной оценки и документированного изменения приложения D. Обязательное разрешение/уведомление и порядок возражения определяет юрист.
5. Обработчик предоставляет оператору сведения о мерах защиты и исполнении поручения по согласованной процедуре. Документы и акты не содержат паролей, ключей, raw dump и лишних ПД.
6. При обнаружении инцидента обработчик без неоправданной задержки уведомляет контакт из G, сохраняет доказательства, ограничивает последствия и передаёт известные категории/масштаб/время/меры. Конкретный внутренний срок в G должен позволять оператору выполнить действующие законные сроки; этот черновик их не заменяет.
7. Запрос субъекта регистрируется и направляется ответственному оператору; личность проверяется без избыточного сбора. Доступ, исправление, прекращение, экспорт и уничтожение выполняются в согласованной области с фиксацией исключений.
8. При прекращении цели/договора стороны оформляют возврат/выгрузку в согласованном формате, прекращение доступа, уничтожение либо законно обоснованное ограниченное хранение. Для backup определяются срок вытеснения и запрет восстановления удалённых данных обратно в рабочую систему. Итог — акт, а не флаг isActive.
9. Ответственность, порядок проверок, споры, уведомления и приоритет основного договора заполняются юристом. Проект не ограничивает права субъектов и обязанности сторон законом.
