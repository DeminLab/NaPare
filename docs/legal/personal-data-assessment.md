# Персональные данные: исходные сведения для оценки

Дата: 22 октября 2026. Читатель: оператор, ответственный за ПД и специалист по ИБ. Тип: инженерный обзор исходников с вопросами для юриста, **не юридическое заключение и не аттестация**.

## Предмет и результат

[Карта данных](../privacy/data-map.md) перечисляет модели, поля, логические хранилища, цели, неподтверждённые основания и сроки по каждому классу. Проверена база `9965e9a`; новые PR учтены отдельным разделом. Production, договоры и фактические количества субъектов не исследовались. Поэтому уровень защищённости нельзя добросовестно утвердить по одному репозиторию.

Для планирования рассматриваем **сценарий специальных категорий**: `Absence.type=sick`, комментарии, документы и заявления могут содержать сведения о здоровье. `isSensitive` — прикладной флаг доступа, не основание обработки. Аватар в модели не используется для распознавания личности; по коду оснований объявлять весь набор биометрическим не найдено. Содержимое пользовательских файлов отдельно не проверялось.

## Рабочие сценарии уровня защищённости

Ниже условные варианты по пунктам 9–12 [ПП № 1119](https://www.consultant.ru/document/cons_doc_LAW_137356/8c86cf6357879e861790a8a7ca8bea4227d56c72/). Это не выбор типа угроз по факту отсутствия найденной уязвимости. Студенты не приравниваются автоматически к сотрудникам оператора.

| Условия, которые должен подтвердить оператор | Условный результат для планирования |
| --- | --- |
| Специальные категории; актуальны угрозы типа 1 | УЗ-1 |
| Специальные категории; угрозы типа 2; менее 100 000 субъектов, не являющихся сотрудниками | УЗ-2 |
| Специальные категории; угрозы типа 3; менее 100 000 таких субъектов | УЗ-3 |
| Специальные категории; угрозы типа 3; более 100 000 таких субъектов | УЗ-2 |
| Только иные категории; угрозы типа 3; менее 100 000 таких субъектов | УЗ-4, лишь если отсутствие специальных/биометрических категорий подтверждено всей обработкой |

**Предварительная гипотеза пилота:** УЗ-3 возможен только при документально подтверждённых угрозах типа 3 и количестве субъектов ниже указанного порога. До модели угроз это не утверждённый уровень. При угрозах типа 2 для описанного пилота планировать УЗ-2; тип 1 меняет результат. Для ровно 100 000 и смешанных контуров специалист сопоставляет полный текст требований; таблица не расширяет нормативные формулировки по аналогии.

Репозиторий не подтверждает ни фактическое число субъектов, ни тип угроз. Отдельный on-premise вуз и общая SaaS-БД — разные границы оценки. Число студентов одного пилота нельзя выдавать за число субъектов общей системы, включая архив/backup и другие вузы.

## Вопросы, без которых оценка не завершается

| Вопрос / доказательство | Кто предоставляет | Статус |
| --- | --- | --- |
| Оператор по каждой цели: вуз, поставщик или оба; полномочия и поручения | Руководство и юрист | Не подтверждено |
| Категории субъектов, несовершеннолетние, количество текущих и архивных записей | Вуз/оператор | Не подтверждено |
| Основание обработки здоровья; допустимый состав, отдельное согласие либо иное применимое основание | Юрист | Не подтверждено |
| Границы ИСПДн, модель угроз, типы 1/2/3, уровень и перечень мер | Ответственный за ИБ | Не утверждено |
| Основание и срок **каждого** класса из карты; исключения удаления | Юрист и архив/учебный офис | Не утверждено |
| Локация БД/реплик/файлов/backup/логов и удалённого сопровождения | Инфраструктура/подрядчики | Не подтверждено |
| Реестр получателей, договоры, уведомления регулятору и оценка внешних передач | Оператор/юрист | Не подтверждено |
| Учёт запросов субъектов, инцидентов, уничтожения и проверок контроля | Ответственный за ПД | Не подтверждено |

## Меры: код и эксплуатационные пробелы

| Область | Подтверждено исходниками / локально | Нужное доказательство эксплуатации |
| --- | --- | --- |
| Доступ | JWT, sessionVersion, прикладной tenant scope; миграция 29 включает FORCE RLS, runtime не должен иметь SUPERUSER/BYPASSRLS | Роли production, применённые политики, индивидуальные учётные записи, пересмотр полномочий |
| Изоляция | Есть локальные SQL и HTTP negative tests; полный бизнес-охват всех маршрутов остаётся открытым | Регрессионные сценарии релиза, контроль доступа персонала/подрядчиков |
| Регистрация действий | AuditLog и отдельные журналы решений | Защита журналов от изменения, фактическое содержание/доступ/сроки, синхронизация времени |
| Секреты | Хеш пароля; Moodle token шифруется AES-GCM | Хранилище/ротация ключей, доступ оператора, восстановление и отзыв; TLS фактической площадки |
| Восстановление | В PR 2 отдельные encrypted dump/restore scripts и локальный drill | Внешняя копия, изолированное восстановление, RPO/RTO и акт проверки на инфраструктуре оператора |
| Уязвимости | Зафиксирован обзор зависимостей; high/critical устранены в проверенном CI, известный moderate отражён отдельно | Повторный контроль точного релиза и регламент исправлений |
| Уничтожение | Сейчас деактивация аккаунта | Реальная процедура удаления/обезличивания и обработка резервных копий ещё не реализованы |

Соответствие группам мер [приказа ФСТЭК № 21](https://www.consultant.ru/document/cons_doc_LAW_146520/2ff7a8c72de3994f30496a0ccbb1ddafdaddf518/) должен устанавливать специалист после утверждения угроз и уровня. Наличие RLS/Docker/шифрования не означает сертификацию или выполнение всех мер. Применимость дополнительных требований к государственным системам и средствам криптозащиты определяется отдельно.

## Нормативные источники и предел проверки

- [152-ФЗ на сайте Минтруда](https://mintrud.gov.ru/docs/laws/130): сверены темы целей/оснований, специальных категорий, отдельного согласия, поручения, локализации и внешних передач. На странице перечислены изменения по 24 июня 2025; она **не подтверждает полноту редакции на октябрь 2026**. Перед утверждением документов юрист сверяет действующую редакцию в официальном опубликовании.
- ПП № 1119 и приказ № 21 выше: прочитан нормативный текст в справочной системе; это не самостоятельное подтверждение отсутствия последующих изменений. Прямой сайт ФСТЭК и портал РКН в текущем просмотре недоступны, статус их актуальных форм не подтверждался.
- [Портал РКН](https://pd.rkn.gov.ru/operators-registry/notification/) — адрес для оператора, **не доказательство подачи уведомления**. Никакие заявления/согласия от имени владельца не отправлялись.

Существующий [обзор готовности](compliance-readiness.md) — снимок 20 октября; поправки по RLS и новые документы не отменяют его эксплуатационные блокеры. Проекты [поручения](data-processing-agreement-draft.md), [политики](privacy_policy.md) и [согласий](consent-drafts.md) предназначены для заполнения и правовой проверки. Публикация или подписание ими не выполнены.
