# Студенческое расписание без сети

Статус: реализация в отдельной ветке `codex/p2-student-offline`, 22 октября 2026. Production не изменялся. Изменения student-каталога явно разрешены владельцем в чате плана улучшений.

## Что доступно

После входа и активации service worker приложение загружает текущую неделю и сведения о подготовке к её парам. При повторном открытии `/student/` без сети worker возвращает самостоятельный экран расписания: он работает без загрузки Next.js chunks. Выберите день текущей недели; видны предмет, время, преподаватель, аудитория, описание изменения и сохранённые задания. Указано время последнего сохранения. Отсутствие сохранённых пар не называется отсутствием занятий.

Подготовка включает название, описание и срок задания. Файлы, их URL, переписка, личные заметки, медицинские сведения, профиль и токены не сохраняются в новом кэше. Существующие локальные снимки других разделов этим выпуском не мигрируются. Для пары без данных показывается действие: открыть её при подключении. Offline-экран ничего не отправляет и не принимает учебные решения.

## Границы кэша

- Только успешные GET `/api/v1/schedule/range`, `/api/v1/my-day`, `/api/v1/pair-spaces/:lessonId` с student identity. У расписания допускаются только даты, timezone и pagination, без фильтра чужой группы/преподавателя.
- Из ответа сохраняется фиксированный набор полей; API responses целиком, HTTP Authorization, cookie и HTML кабинета не сохраняются.
- Ключ: `universityId/studentId` из текущей локальной сессии. Offline-документ читает только этот раздел. Это локальное разделение данных, а не замена серверной JWT/RLS авторизации.
- TTL семь дней; до 120 снимков, не более 500 занятий в ответе и 512000 символов исходного JSON. Worker удаляет устаревшие/избыточные записи, экран повторно проверяет TTL. Автозагрузка ограничена первой страницей до 100 занятий и первыми 60 PairSpace; открытая пользователем пара тоже обновляет кэш. При большем расписании покрытие подготовки неполное и не должно считаться подтверждением сохранения всей недели.
- Выход очищает весь новый offline-кэш. Сообщение worker отменяет сохранение ещё не полученного ответа; снятый токен сразу лишает offline-экран выбранной identity. На самом экране есть отдельная кнопка удаления кэша.
- Кэш не гарантирует наличие последних переносов/отмен. При подключении источником истины остаётся API. Браузер может удалить своё хранилище; недоступный storage не блокирует online-кабинет.

Service worker требует HTTPS, localhost допускается для разработки. В Cache API срок хранения задаётся приложением, поэтому TTL проверяется явно. Основание: [MDN — использование service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers), [MDN — Cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache).

## Проверки

```powershell
pnpm --filter @napare/web-student test:offline
pnpm --filter @napare/web-student exec tsc --noEmit
node scripts/verify-role-workspace-boundaries.cjs
node scripts/verify-ai-documentation.cjs
pnpm lint
pnpm lint:docs
```

Focused Node tests выполняют сгенерированный worker с fixture CacheStorage: разделение identity, минимизация данных, запрещённые запросы, logout/in-flight и TTL/лимит. Это не проверка браузера или устройства. Данные для браузерного сценария синтетические; реальный backend, установленный Android APK и production-домен требуют отдельной проверки.

Локальный Playwright/Chromium, 22 октября: реальный Next.js dev и затем production build/start, service worker, синтетический backend. При отключённой сети новая навигация и новая вкладка открыли расписание и задание; другой student/university не получил чужих записей; кнопка удаления очистила кэш. На 320 px нет горизонтального переполнения, скриншот проверен визуально (`output/offline-320.png`, ignored). Это отдельный offline-экран, поэтому для открытия не нужны сохранённые Next.js chunks. Первая попытка проверки столкнулась с dev HMR reload во время отключения сети; повтор без обновления исходников и повтор на production build прошли. Ошибка favicon в offline-режиме не влияет на чтение расписания. Все 6 focused tests, student typecheck, production build, root lint, docs lint и оба repository guards прошли.
