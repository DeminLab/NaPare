# Привязка аккаунта через Telegram

Telegram используется только как дополнительная связанная идентичность. Вход в NaPare и привязка MAX остаются основаны на штатных проверках этих каналов; пароль не отправляется в Telegram.

В репозитории реализован backend webhook и страница выпуска одноразовой ссылки; отдельного процесса, который создаёт бота или устанавливает Telegram webhook автоматически, нет. Нужно создать бота в Telegram BotFather и вручную настроить webhook по инструкции ниже.

## Поток пользователя

1. Пользователь входит в NaPare по учётной записи университета и открывает `/connections`.
2. `POST /api/v1/auth/telegram/link` требует JWT и выдаёт deep link бота с криптографически случайным одноразовым кодом.
3. Пользователь открывает ссылку в личном чате бота. Telegram присылает `/start <code>` в webhook.
4. Backend проверяет `X-Telegram-Bot-Api-Secret-Token`, погашает код в транзакции и связывает Telegram user ID с аккаунтом. Код действителен 10 минут; новая ссылка аннулирует предыдущую.
5. Бот подтверждает результат в личном чате. Повторная привязка Telegram ID к другому аккаунту и замена уже привязанного Telegram отклоняются.

После привязки пользователь может отдельно включить Telegram-уведомления в настройках сайта. Канал выключен по умолчанию; обычные категории и тихие часы аккаунта применяются до отправки, а `urgent` проходит по общему правилу уведомлений. Бот отправляет текст события и кнопку с безопасной внутренней ссылкой на `PUBLIC_APP_URL`. Доставка выполняется последовательно через ограниченную очередь в памяти backend-процесса: при его остановке ожидающие сообщения теряются, повторная отправка пока не гарантируется.

Связать Telegram и MAX автоматически нельзя: запуск MAX подтверждается только подписанным MAX `initData` внутри MAX WebApp. После привязки Telegram пользователь по-прежнему открывает сайт в MAX и выполняет MAX-связь отдельно.

## Настройка

Создайте бота в Telegram BotFather. Задайте на backend `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без `@`), `TELEGRAM_WEBHOOK_SECRET` длиной от 32 до 256 символов из `A-Z a-z 0-9 _ -` и HTTPS origin `PUBLIC_APP_URL`. Переменные бота задаются только вместе; в Compose они передаются backend-контейнеру.

Установите webhook на `https://napare.sano.ru/api/v1/integrations/telegram/webhook`, передав тот же `TELEGRAM_WEBHOOK_SECRET` как Telegram Bot API `secret_token`. Установите `allowed_updates` только в `message`. Секрет webhook не является токеном бота и не должен попадать в URL или репозиторий.

В production миграция `1700000000015-TelegramAccountLink` добавляет уникальный Telegram ID и таблицу одноразовых challenge-кодов. Перед выпуском следует применить миграцию, настроить webhook и проверить привязку/истечение кода в закрытом тестовом чате.
