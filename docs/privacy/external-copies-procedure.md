# Внешние копии после удаления аккаунта

Дата: 25 октября 2026. Техническая процедура P2-1 для оператора НаПаре и представителя вуза. Подготовлена по коду, над реальными данными не выполнялась. Ответственные, основания, сроки хранения и ответа ещё не утверждены оператором. Пользователь сообщил, что внешние подключения не подготовлены.

## Граница квитанции API

[AccountErasureService](../../apps/backend/src/users/account-erasure.service.ts) очищает профиль и приватные наборы активной БД, отзывает доступ и сохраняет учебный архив под UUID. URL вложений очищаются, но байты по этим адресам не удаляются. Собственные audit payload/IP/userAgent очищаются; записи других актёров и внешние журналы остаются исключениями. [JSON export](personal-data-export.md) не содержит внешние архивы и байты файлов. Квитанция подтверждает только перечисленные операции активной БД.

Пользователь выбрал индивидуальную учебную историю без имени и контактов. UUID, группа, даты и текст могут позволить обратную идентификацию: это псевдонимизация. Процедура не разрешает автоматически уничтожать учебный архив или обязательные финансовые документы. Их состав, основания, срок и доступ определяет оператор с вузом. См. [контракт удаления](account-deletion.md) и [карту данных](data-map.md).

## Открытие дела

1. Ответственный принимает запрос через утверждённый канал и проверяет личность/полномочия. Пароль и секреты интеграций не запрашивает. После удаления сопоставляет квитанцию с защищённым журналом: одного публичного UUID недостаточно для выдачи данных.
2. Фиксирует номер дела, аккаунт/вуз, время и версию операции, результат API и реально используемые системы. Проверяет [реестр площадок](../legal/rf-deployment-assessment.md). Неизвестный провайдер означает открытый вопрос, а не отсутствие копии.
3. По каждому классу выбирается согласованное действие: удалить, ограничить, сохранить по основанию, запросить действие у владельца источника либо установить расположение. Записываются исполнитель, основание и утверждённый срок. Универсальные юридические сроки эта инструкция не задаёт.
4. Пока соответствие внешних объектов доступно, уполномоченный оператор сохраняет минимальный закрытый перечень object IDs и владельцев систем. Self deletion ради сбора полного досье не блокируется. После очистки ссылок используются разрешённые журналы/ответы владельца хранилища. Если соответствие установить нельзя, пробел фиксируется явно.

Реестр дел, archiveCode и внешние ID сами могут идентифицировать человека. Они хранятся с ограниченным доступом и утверждённым сроком отдельно от Git, публичных PR, обычных логов и уничтожаемого профиля. Signed URLs, токены, документы и полные логи в чат/CI artifacts не переносятся.

## Обработка конкретных копий

| Система | Действие ответственного | Доказательство и ограничения |
| --- | --- | --- |
| Активная PostgreSQL | Сверить квитанцию, tombstone/отзыв доступа, очистку приватных наборов и сохраняемые классы через разрешённую служебную область | Номер операции, время, версия и результат без секретов. Admin deactivate не является удалением |
| Байты вложений, аватара, портфолио | Установить origin/provider, объект, версии и thumbnails. Проверить принадлежность и общие учебные материалы; выполнить согласованное удаление приватных объектов и производных копий | Квитанция провайдера и повторная проверка. Удаление URL не подтверждает удаление байтов. Недоступный провайдер остаётся открытым |
| CDN/прокси/ссылки | Установить cache keys/сроки, отозвать собственные ссылки, выполнить поддерживаемый purge | Квитанция purge и повторная проверка. Независимые скачанные копии не находятся под контролем платформы |
| Moodle/СИБИТ | Представитель вуза определяет владельца и отдельные основания учебной истории; передаёт минимальный разрешённый запрос владельцу источника | Ответ с действиями, исключениями и сроками. Удаление привязки НаПаре не удаляет студента, оценки и файлы в источнике |
| Push/MAX/Telegram | Подтвердить отзыв привязок и отсутствие новых целей; внешнюю историю обрабатывать по фактическим возможностям провайдера | Разделить токен, локальную отписку, уже отправленные сообщения и копии получателей. Принятие провайдером не подтверждает удаление OS notification. [WebPush](../clients/webpush.md) |
| Логи/APM/Sentry/audit/выгрузки поддержки | Установить потоки, допустимые идентификаторы и сроки; применить согласованное удаление/редакцию/ограничение, учесть append-only и обязательные записи | ID операции/наборов, срок остаточного хранения и доступ. Redact код не доказывает очистку уже отправленного внешнего лога |
| Redis/очереди/dead letter | Проверить payload, AOF/RDB и зависшие задания; исключить новую доставку удалённому аккаунту | Проверка конкретных ключей/заданий. FLUSHALL и массовое удаление очередей затронут других людей и не входят в процедуру |
| Банк/финансовые документы | Определить стороны и обязательные сохраняемые записи; запросить допустимое действие по договорной процедуре | Сохранение расчётных документов отделить от необязательных контактов. Self deletion не означает возврат платежа/удаление у банка. Выплаты студентам исключены моделью |
| Backup/реплики/WAL/snapshots | Перечислить копии, ключи, сроки и доступ. Применить утверждённую политику выбытия/перезаписи с учётом неизменяемости и восстановления ниже | ID копии, срок/квитанция удаления и restore drill. Зашифрованная копия остаётся копией |

Автоматические внешние удаления, provider acknowledgements, поиск байтов по URL и сверка внешних журналов этой документацией не реализуются. Массовые команды удаления не предлагаются.

## Не вернуть удалённый профиль из backup

[Recovery script](../../scripts/postgres-recovery.cjs) проверяет изолированную пустую loopback БД и целостность восстановления, но не повторяет удаления после даты backup. [Runbook](../deployment/runbook.md) не резервирует внешние байты, роли кластера и секреты автоматически.

1. Вести защищённый журнал удалений/ограничений отдельно от восстанавливаемого снимка: минимальный archiveCode, время/версия операции, состав сохранённого и ссылка на закрытое дело. До допуска восстановления проверить полноту, целостность и доступ к журналу.
2. Восстановить только в изолированную среду без пользователей и внешних отправок; зафиксировать cutoff копии и последующие операции. Повторно проверить delivery/connectors: старый dump может вернуть прежние токены и привязки.
3. Сверить восстановленные записи с журналом после cutoff. Для каждого аккаунта выполнить отдельно подготовленное и проверенное восстановление tombstone, очистки и отзыва. Готового административного replay API сейчас нет. Self API с прежним паролем и копирование одной строки users не заменяют обработку связанных наборов.
4. Проверить отсутствие входа/refresh/новых уведомлений/внешней синхронизации удалённых аккаунтов, сохранение согласованного архива и чужих данных. Отдельно сверить файлы/логи/источники.
5. Решение о переключении принять только после подтверждённой сверки. Неполный журнал или неподготовленный replay означают карантин восстановления. Успешный pg_restore сам по себе не подтверждает готовность к эксплуатации.

Внешний encrypted storage, проверка на другой машине и доставка алерта остаются открытыми. Production не изменялся; эта процедура не является свидетельством такого drill.

## Результат и закрытие

Закрытая карточка содержит: номер дела; ответственного; подтверждённую границу запроса; дату/код квитанции API; для каждой системы — действие, основание/срок, исполнителя, время, доказательство без секретов и статус `выполнено / сохранено по основанию / ожидает / не установлено`; остаточные копии; дату повторной проверки; проверяющего.

Ответ человеку разделяет удалённое, сохраняемый учебный архив, внешние действия и неподтверждённые копии. Для ожидающих пунктов указываются конкретная причина, ответственный и утверждённый срок следующего шага. При открытых копиях или индивидуальном архиве нельзя сообщать «все данные удалены».

Дело закрывается по утверждённым оператором критериям с проверяемыми доказательствами. Подготовка этого документа завершает техническую спецификацию процедуры; фактическая обработка внешних копий, юридическое утверждение и эксплуатационная проверка остаются открытыми.
