## Контракт

`GET /api/v1/users/me/export`, Bearer JWT. Доступен каждому активному аккаунту, включая карьерные роли без привязки к вузу. Пользователь определяется только JWT; переданный `userId` не выбирает чужой аккаунт. Исключение в guard разрешает только точный путь экспорта и не открывает академические API.

Ответ — attachment `napare-personal-data.json`, `application/json`, `Cache-Control: no-store, private`. Содержит версию формата, время единого снимка PostgreSQL, `limitations`, `datasets`, число строк каждого набора в `counts` и завершающий признак `complete: true`. Клиент должен проверить корректность JSON и этот признак перед сообщением об успехе. При сбое после начала передачи соединение закрывается: частичный файл не является завершённым экспортом.

## Состав и ограничения

Проекции заданы явно в [каталоге](../../apps/backend/src/users/personal-data.catalog.ts). Выгружаются профиль/контакты/внешние идентификаторы, собственные учебные записи и заявления с доступной историей решений, личные заметки/избранное, настройки/устройства без push-токена, сообщения/задания/файловые метаданные автора, карьерные данные, собственные платёжные операции, назначения и метаданные действий. Строки, относящиеся к прежнему вузу того же человека, не теряются из-за его текущей привязки.

Для действий над чужими записями выдаются ограниченные метаданные вместо чужого полного досье. Идентификаторы других участников не добавляются автоматически. Собственные тексты и уже доступные автору отзывы на его работу включаются; это не автоматический поиск всех упоминаний человека во всех текстах системы.

Исключены passwordHash/sessionVersion, токены устройств и привязки, секреты интеграций, банковские ссылки подтверждения, ключи идемпотентности, полные audit old/new JSON, payload импорта/событий, data/actions уведомлений и тексты ошибок доставки. Эти произвольные JSON могут содержать чужие сведения и секреты; вместо них выдаются безопасные метаданные. Полный запрос к оператору по спорным журнальным сведениям остаётся отдельной процедурой.

Moodle, файлы **по** URL, браузерные копии, backup/WAL и архивы внешних сервисов не скачиваются этим endpoint. Наличие fileUrl не означает выгрузку байтов. Общие каталоги и конфигурация организации не считаются личным набором; ФИО преподавателя из источника без проверенной связи с аккаунтом требует участия оператора. Эти ограничения присутствуют и внутри JSON. Функция не заявляет юридическую полноту ответа на запрос субъекта ПД.

## Границы реализации

Сервис использует `REPEATABLE READ READ ONLY`, выборку по первичному ключу порциями по 100 строк и обратное давление HTTP. Общего лимита в 100 строк нет. Значения пользователя передаются параметрами SQL; имена таблиц/полей берутся из проверенного каталога, `SELECT *` отсутствует. Новые поля приватны по умолчанию. Проверка на реальной схеме требует, чтобы каждый класс сущности имел проекцию либо явное объяснение исключения.

Миграция 37 добавляет к существующим restrictive SELECT policies право чтения только собственных строк внутри узкой `personalData` capability. SQL повторно сопоставляет capability с текущим `actor_id`. UPDATE/INSERT/DELETE policies не расширяются; чужие строки вне текущего вуза остаются закрыты. Обычные запросы без capability работают по прежним правилам. Режим READ ONLY дополнительно запрещает запись самим экспортом.

Одновременно допускается один экспорт на аккаунт и четыре на процесс; занятость возвращает 429/503. Это локальная защита пула, не распределённый лимит между репликами. SQL timeout — 15 секунд на запрос, ожидание HTTP drain — 15 секунд, idle transaction timeout — 60 секунд. Обрыв клиента освобождает transaction/runner и локальную блокировку. Файл экспорта сервером не сохраняется.
