# ADR-0001: Модульный монолит

## Статус
Принято

## Контекст
Команда из 2 человек (CEO/Product + CTO). Нужна быстрая разработка MVP с возможностью масштабирования. Microservices на старте избыточны: сложность деплоя, сетевые задержки, необходимость оркестрации. Монолит упрощает разработку, тестирование и деплой.

## Решение
Использовать **модульный монолит** на NestJS:
- Единый процесс
- Модули: Auth, Schedule, PairSpace, Absences, Notifications, Admin, MyDay
- Чёткие границы между модулями
- Общие инфраструктурные компоненты (common/)
- Взаимодействие через прямые вызовы (не события)

## Преимущества
1. Простота разработки и деплоя
2. Единая транзакция при необходимости
3. Лёгкость рефакторинга
4. Быстрый старт для маленькой команды
5. Единый OpenAPI-спецификация

## Недостатки
1. Ограниченное горизонтальное масштабирование
2. Сбой одного модуля может повлиять на весь процесс
3. Зависимости между модулями

## Масштабирование
При необходимости можно выделить отдельные модули в сервисы (стрangler pattern). Границы модулей уже определены.
