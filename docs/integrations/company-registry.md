# Проверка ИНН компании: адаптер публичного поиска ФНС

24 октября 2026. Статус: реализация P2-2 в отдельной ветке, локальные проверки. Подключены создание компании, сохранение результата, повторная проверка владельцем и интерфейс. Production не изменяется; доступность внешнего реестра не гарантируется.

## Источник и границы

[Публичный сервис ФНС](https://egrul.nalog.ru/) принимает ИНН/ОГРН и возвращает сведения ЕГРЮЛ/ЕГРИП. [Описание ФНС](https://egrul.nalog.ru/about.html) отдельно описывает подписанную PDF-выписку; текущий адаптер её не скачивает и электронную подпись не проверяет. Совпадение поисковой записи не подтверждает принадлежность аккаунта компании, безопасность работодателя или партнёрство с вузом.

23 октября прочитаны HTML формы и [клиентский скрипт версии 1.8.14](https://egrul.nalog.ru/js/index.js?ver=1.8.14&lang=RUS): POST поиска, ticket, GET `search-result`, состояние `wait`, поля `k/i/n/o/e/v`, CAPTCHA. Это наблюдаемый протокол веб-сервиса, а не обещание документированного стабильного публичного API. При изменении протокола адаптер сообщает о недоступности. [Официальный интеграционный доступ](https://www.nalog.gov.ru/rn77/service/egrip2/) использует отдельно предоставляемые атрибуты доступа и файловые выгрузки; он не настроен и этим кодом не заменяется.

Внешние запросы выполняются только при `CAREER_COMPANY_REGISTRY_ENABLED=true`. По умолчанию адаптер возвращает `disabled` без сети. Он принимает только ИНН с корректными контрольными цифрами, использует фиксированный HTTPS-host и не следует redirect. В поиск передаётся только ИНН, без имени/почты/пароля пользователя; ticket и полный ответ не журналируются. До двух одновременных запросов на процесс, до трёх проверок готовности ticket, общий timeout 10 секунд, максимум 256 KiB на ответ. Это технические ограничения; они не гарантируют доступность ФНС и не заменяют ограничения повторных попыток конкретной компании и пользователя.

## Результаты

| Статус | Значение |
| --- | --- |
| `disabled` | Внешняя проверка выключена; запроса не было |
| `unavailable` | Сеть, HTTP, размер/формат ответа, ожидание или локальная занятость не позволили проверить запись |
| `captcha_required` | ФНС требует CAPTCHA; адаптер прекращает поиск и не решает её автоматически |
| `not_found` | Получен завершённый пустой результат |
| `ambiguous` | Нет единственного точного совпадения ИНН и вида реестра |
| `matched` | Единственное совпадение: ИНН, вид ЮЛ/ИП, имя и ОГРН/ОГРНИП; это факт поискового совпадения |
| `inactive` | В совпавшей записи явно указано прекращение деятельности или недействительность регистрации |

`checkedAt` — время завершения попытки НаПаре, включая неуспешную; не дата обновления реестра и не дата юридического подтверждения. Для `disabled` оно null. Результат содержит только ИНН, ограниченные строковые имя/ОГРН, статус, фиксированный источник и короткую техническую причину. Чужой результат, дубликат, неправильный вид реестра или неоднозначный ответ не становится `matched`. Подтверждение партнёрства карьерным центром должно остаться отдельным решением.

## Регистрация, хранение и повторная проверка

`POST /api/v1/career/companies` теперь требует `inn` из 10/12 цифр. DTO проверяет формат, адаптер — контрольные цифры. Старые клиенты без поля получат 400; существующие карточки сохраняются с `inn=null`, `registryStatus=not_checked`. Работодатель создаёт компанию с результатом попытки; недоступность/выключенная проверка явно сохраняются и не превращаются в успешное совпадение. Компания, назначение владельца и pending-партнёрство сохраняются одной транзакцией после завершения сетевого запроса.

Миграция 39 добавляет только поля `career_company`: ИНН, статус, время попытки/начала, имя реестра, ОГРН/ОГРНИП, короткую причину и версию проверки. Существующие роли, партнёрства и платежи не переоформляются. Down отказывается удалять поля, если есть сохранённые ИНН; сначала нужна отдельная подготовленная оператором процедура экспорта/прекращения хранения.

`POST /api/v1/career/companies/:id/registry-check`, JWT владельца, тело `{}` для существующего ИНН либо `{inn}` для старой карточки без ИНН. Изменять уже закреплённый ИНН через этот маршрут нельзя. Обычный сотрудник компании, чужой владелец и вуз без назначения владельца получают 403 до обращения к ФНС. Throttler ограничивает три повторные проверки в минуту на IP/tracker; отдельно БД ограничивает компанию минутой между началами попыток. Блокировка компании и повторная проверка назначения владельца защищают начало/завершение; сеть не держит транзакцию открытой. Версия не позволяет позднему ответу затереть более новую попытку. Если права отозваны в полёте, результат не записывается; оставшееся `checking` можно заменить новой разрешённой попыткой после минуты.

На карточке показываются статус, ИНН, реестровое имя/номер, время попытки, публичная ссылка ФНС и отдельное пояснение о партнёрстве. Владелец может повторить проверку или заполнить ИНН старой карточки. CAPTCHA не решается автоматически. Поле ИНН отправляется только ФНС, не стороннему посреднику. Совпадение не доказывает контроль аккаунта над организацией; решение карьерного центра остаётся отдельным.

Для ИП имя/ИНН могут быть персональными данными. Организационная карточка не стирается удалением пользовательского аккаунта; это дополнено в preview и квитанции удаления. Основание, сроки хранения и процедура оператора отражены как нерешённые вопросы в [карте ПД](../privacy/data-map.md), а не как установленная юридическая гарантия.

## Фактические проверки

- 23 focused unit-сценария с синтетическими HTTP-ответами: оба формата ИНН, выключенная сеть, ЮЛ/ИП, точное совпадение, прекращение деятельности, пустой/чужой/повторный результат, CAPTCHA, неверный ticket, изменение схемы, ожидание, лимит тела и освобождение concurrency lease.
- 12 настоящих JWT/HTTP/PostgreSQL сценариев прошли: регистрация, миграция 39, сохранённые поля, pending-партнёрство, запрет чужим/сотрудникам, cooldown, неизменяемый ИНН, четыре состояния внешнего ответа, отзыв владельца в полёте, поздний ответ после новой версии проверки, полный откат и защита down. ФНС в них подменена.
- Backend unit: 43 suites / 453 tests; guard probes: 4451 passed, 360 маршрутов. Backend/portal typecheck и lint прошли. 10 account-erasure PostgreSQL сценариев повторно прошли после добавления явного предупреждения о сохранённых реестровых реквизитах.
- Один прямой read-only запрос адаптера к живой ФНС 24 октября дал `matched`, точный ИНН, имя и ОГРН. Это проверка одного публичного запроса, не SLA и не криптографическая проверка выписки.
- Browser: настоящий Next/Nest/PostgreSQL с подменённым только ФНС. Создание компании, ошибочный ИНН с сохранением ввода, совпадение и CAPTCHA как разные статусы, cooldown, 320/768/1024/1440 без overflow, 0 pageerror. Новые две панели: axe-core 4.10.3 — 0 violations / 0 incomplete по WCAG 2/2.1 A/AA. Полный экран содержит 7 существовавших находок contrast (back/eyebrow/текст header, success, payments empty, muted partnership counter и empty list). Header/навигация не изменены; эти находки не скрываются узкой проверкой панели. Полного соответствия WCAG не заявляется.

Не проверены production, другие устройства, устойчивость публичного сервиса при постоянной нагрузке и юридическая достаточность совпадения. Флаг в production не включался; настройку интеграционного доступа ФНС этот блок не выполняет. Нельзя считать `disabled/unavailable` успешной верификацией.
