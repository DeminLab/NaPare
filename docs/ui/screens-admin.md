# Экраны администратора вуза и суперадмина (Web)

> Проектная спецификация кабинета вуза; не трактуйте каждый экран/действие как реализованный endpoint.

## A01. Структура вуза

- Дерево / список: Факультеты → Курсы → Группы
- CRUD групп и факультетов
- Назначение кураторов группам

## A02. Расписание

- Загрузка файла (Excel / CSV / iCal)
- Маппинг колонок (если нужно)
- Статус последней синхронизации
- Логи ошибок
- Кнопка «Запустить синхронизацию»
- История загрузок

## A03. Пользователи и роли

- Поиск пользователей
- Назначение ролей: Teacher, Curator, UniversityAdmin
- Привязка преподавателя к парам / группам

## A04. Базовая статистика

- Количество активных студентов
- % преподавателей с контентом
- Количество отсутствий за период
- (простые графики)

## A05. Первичное подключение и публикация

- Владелец платформы создаёт или выбирает вуз, настраивает факультеты и группы, затем создаёт учётную запись администратора.
- Владелец передаёт логин, контактный email и начальный пароль защищённым способом; мастер не сохраняет пароль и не выполняет вход за администратора.
- Администратор входит через общий экран `/login`, затем продолжает мастер по `/deanery/onboarding?step=3`.
- Импорт файла выполняется внутри мастера. Для Moodle или СИБИТа администратор может перейти в «Источники данных» и вернуться к шагу импорта.
- После проверки администратор отдельно включает публикацию в настройках вуза. По умолчанию публичная публикация выключена.

## SA01. Суперадмин

- Список вузов
- Подключение нового вуза
- Управление коннекторами
- Общая аналитика по платформе
- Управление доступами / тарифами (на будущее)
