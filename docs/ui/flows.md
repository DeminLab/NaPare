# Пользовательские потоки НаПаре

## 1. Регистрация студента (полный happy path)

1. Пользователь открывает приложение / сайт / MAX Mini-App
2. Экран приветствия → «Зарегистрироваться»
3. Ввод телефона → «Получить код»
4. Ввод SMS-кода
5. Экран согласия на ПДн (обязательный чекбокс)
6. Выбор вуза (поиск + список)
7. Выбор факультета
8. Выбор курса
9. Выбор группы
10. Ввод имени и фамилии (+ аватар опционально)
11. Короткий онбординг-тур (3–4 экрана)
12. Попадание на «Мой день»

**Время:** ≤ 2 минуты при нормальном интернете.

## 2. Первый запуск преподавателя

1. Регистрация (телефон или email)
2. Экран «Ожидание назначения роли»
3. Админ вуза назначает роль Teacher и привязывает пары
4. Push / уведомление «Вам назначена роль преподавателя»
5. Вход → экран «Мои пары»

## 3. Публикация контента преподавателем

1. Открыть «Мои пары»
2. Выбрать пару
3. Нажать «Добавить» → выбрать тип (Объявление / ДЗ / Файл)
4. Заполнить минимум полей
5. Опубликовать
6. Студенты группы получают push

**Целевое время:** ≤ 30–40 секунд.

## 4. Установка статуса отсутствия

1. Студент открывает «Статус» или виджет на «Мой день»
2. Выбирает тип статуса
3. Выбирает период
4. Система показывает «Будет затронуто N пар»
5. Подтверждает
6. Куратор получает уведомление
7. Куратор в дашборде подтверждает / отклоняет
8. Студент (опционально) получает уведомление о решении

## 5. Обработка изменения расписания

1. Коннектор / админ загружает новое расписание
2. Backend детектит изменения
3. Создаются LessonChange
4. Notification Service отправляет push студентам и преподавателям
5. В «Мой день» и в расписании появляется индикатор «Изменено»
6. В пространстве пары видна история изменений

## 6. Просмотр пространства пары студентом

1. Из «Мой день» или Расписания тап по паре
2. Открывается Пространство пары
3. Вкладки: Объявления | ДЗ | Файлы | Обсуждение
4. Студент может:
   - Прочитать объявление
   - Отметить ДЗ как сданное
   - Скачать файл
   - Написать сообщение в обсуждение
