# Аудит доступности студенческого приложения

Дата: 22 октября 2026. База: интеграционный кандидат `a2e0565` (PR 13), не production. Аудит для разработчика и владельца: находки, область доказательства и порядок исправления. Изменений интерфейса этот отчёт не вносит.

## Метод и область

Ориентир — [WCAG 2.1 W3C](https://www.w3.org/TR/WCAG21/), уровни A/AA; дополнительно прочитаны [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). Последние — инженерные рекомендации, не замена нормативным критериям. Найденные ниже дефекты не позволяют заявлять соответствие AA.

Локальный Chromium через Playwright CLI, настоящий Next dev, axe-core **4.10.3** из npm с правилами `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`. Основной прогон: 14 состояний × две ширины 1440/320, высота 900. API — синтетические ответы пустого/недоступного состояния; это не реальный учебный аккаунт и не все состояния компонентов. Проверялись весь документ, overflow, page errors и результаты incomplete. Фоновые preload-запросы service worker могли завершаться ошибкой при отсутствии backend; это не доказательство работы offline. Проверки offline описаны отдельно.

Результат основного прогона: 28 состояний без page errors и горизонтального переполнения. Единственный тип автоматических violations — `color-contrast`; incomplete по contrast/ARIA сохраняются для ручной проверки и не считаются passed. Отсутствие других axe findings не является доказательством соответствия всем критериям.

## Подтверждённые находки

### A01 — P1: контраст вторичного текста и меню

`apps/web-student/src/app/globals.css:447` — подписи групп меню `#9aa5ba` на белом: измерено axe **2,48:1** при 10 px. На desktop проявляется на всех проверенных рабочих страницах. Исправить цвет на проверенную семантическую переменную с достаточным контрастом; маленький размер/начертание не дают исключения.

`apps/web-student/src/app/globals.css:461` — локальный secondary token `#71809e`: измерено **3,97:1** на белом у обычного текста 14 px, например в attendance/check-in и curation. Аналогичные жёсткие цвета: строки 499/512. Перепроверить все фактические фоны и темы после изменения. Критерий: [1.4.3](https://www.w3.org/TR/WCAG21/#contrast-minimum).

### A02 — P2: контраст неактивных разделов профиля

`apps/web-student/src/app/(student)/profile/page.tsx:71` — кнопки разделов с `text-slate-500` на `#f7f8fc`: axe **4,48:1**, ниже порога для обычного текста. Это интерактивные доступные элементы, не disabled. Исправление должно сохранить различимость выбранного состояния и focus. Критерий 1.4.3. Номер строки проверять по указанной базе при будущих изменениях.

### A03 — P2: заголовок вкладки не различает страницы

`apps/web-student/src/app/layout.tsx:6` — общий title «НаПаре — Студент»; отдельные страницы не задают заголовок своей темы. Вкладки расписания, профиля и настроек не различаются названием. Добавить маршрутные title с названием приложения; проверить browser back/forward и динамические страницы. Критерий: [2.4.2](https://www.w3.org/TR/WCAG21/#page-titled). Это ручная находка; axe проверяет наличие title, но не его достаточность для различения тем.

### A04 — P2: отсутствует ожидаемая обратная связь о сохранении

`apps/web-student/src/app/(student)/settings/page.tsx:215`, `:229`, `:248` — вызывается `toast` об успешном сохранении. `apps/web-student/src/components/ui/Toast.tsx:17` задаёт noop без provider; в root/student layout provider не подключён. Успешное действие может убрать dirty bar без обещанного сообщения. Это подтверждённый по коду функциональный дефект обратной связи; отсутствие самого сообщения не выдаётся автоматически за доказанное нарушение 4.1.3.

Если подключать provider, его текущая разметка `Toast.tsx:48` не имеет live region, а контейнер снимается через 3 секунды. Нужны объявляемый status, доступная длительность и проверка NVDA, без принудительного переноса фокуса. Ориентир: [4.1.3](https://www.w3.org/TR/WCAG21/#status-messages).

Дополнительная браузерная проверка с synthetic PATCH: после редактирования имени и «Сохранить профиль» dirty button исчез, «Профиль сохранён» в DOM отсутствует, содержательного status нет. Settings и profile возвращают одинаковый document.title. Это проверка интерфейсной реакции, не сохранения реальных персональных данных.

### A05 — P2: публичная landing выходит за мобильный viewport

`apps/web-student/src/app/page.tsx:28` — в блоке ролевых карточек на viewport 320 px ширина документа **333 px**, правый край трёх article — **332,875 px** при left=16. Это отдельная страница `/student`, не кабинет today. Проверить min-width/grid/flex потомков RolePreview (`page.tsx:26`), разрешить перенос и ограничить широкое превью внутри контейнера, сохранив содержание. Горизонтальное переполнение подтверждено DOM-измерением; применимость исключения для двумерного превью и полный [1.4.10](https://www.w3.org/TR/WCAG21/#reflow) требуют ручной оценки. Не скрывать проблему глобальным overflow-x:hidden.

На login также подтверждён контраст текста/ссылки условий: **2,56:1** (`text-slate-400` на белом, 12 px). Root landing имеет 46 contrast-узлов в каждом из двух состояний. Их проверяют как отдельные реализации, не исправлением одного secondary token кабинета.

## Проверенное положительное поведение и долг компонентов

В общем WorkspaceShell есть skip link к `workspace-content`, main landmark, именованные кнопки поиска/меню, Escape и focus trap для общих overlay, восстановление фокуса и inert фона. Source: `packages/ui/src/WorkspaceShell.tsx:89`, `:110`, `:163`, `:175`. Это наблюдение по коду; полная ручная проверка всех веток overlay ещё нужна. Root задаёт lang=ru. В globals есть focus-visible и prefers-reduced-motion; факт наличия CSS не доказывает каждый элемент/анимацию.

Браузер дополнительно подтвердил Ctrl+K: фокус внутри именованного search dialog; Escape закрывает окно. Полный обход Tab/Shift+Tab, возврат к каждому возможному инициатору и NVDA этим шагом не проверены.

Неиспользуемые локальные primitives не считать ошибками открытых маршрутов: `Input.tsx:16` рисует label без связи с input; `Modal.tsx:24` не задаёт имя dialog, focus trap/возврат/Escape; `TabBar.tsx:25` не сообщает выбранное состояние. По импортам действующие settings используют Input из `@napare/ui`, а общий shell — собственные overlay. Если эти primitives будут подключаться, устранить долг до использования.

## Что остаётся проверить

Ручной NVDA/клавиатура на заполненных данных, длинные имена/ошибки/формы, focus при изменении страницы и открытии файлов, увеличение текста 200%, reflow и текстовые интервалы, все темы/акценты/disabled/hover/focus контрасты, status/error announcements, тайминги уведомлений, текущие labels/отношения внутри расписания и чек-листов, мобильные touch/ориентация, вложенные материалы и внешние страницы. Axe incomplete требует ручного решения. Для полного AA нужно проверять все применимые критерии и полные процессы, а не количество passed rules.

Первоначальный порядок исправления: A01 → A02 → titles → обратная связь сохранения; затем заполненные процессы и ручная проверка. После ревью PR 15 владелец явно разрешил исправления A01–A05; повторное разрешение не требуется. Подтверждение полного AA по-прежнему отсутствует.

## Исправления A01–A05 после согласования

В отдельной ветке `codex/p2-student-accessibility-fixes` исправлены измеренные контрастные пары, включая светлые подписи меню/secondary, профильные разделы, login и публичные preview. У ролевых карточек min-width и grid tracks допускают сжатие/перенос; при 320 px горизонтальное переполнение устранено. Серверные layouts задают отдельные заголовки для всех маршрутов; у динамической пары absolute title сохраняет название приложения при вложенном layout. Формы настроек выводят постоянный inline `role=status`, очищаемый при следующем редактировании/запросе, вместо вызова отсутствующего toast provider. Navigation/header implementations, Avatar и logo assets не менялись.

Повторный прогон использовал отдельный Chromium context с **serviceWorkers=block**, чтобы все API fixtures перехватывались страницей. В начальном аудите worker мог обходить перехват schedule/pair-space запросов; поэтому подписи «пустая неделя/месяц» в первоначальной таблице не доказывают именно успешный пустой ответ. Контрастные находки, DOM overflow и title/save наблюдения остаются фактическими; новый прогон уточняет состояние: пустые коллекции, source unavailable и синтетическая заполненная пара.

После исправлений: 36 axe-снимков (те же 16 маршрутов и две дополнительные settings-секции на 1440/320), **0 violations, 0 page errors, overflow=false**. Incomplete по contrast/ARIA остаются вопросами для ручной проверки, включая декоративные gradient previews; они не объявляются passed. Это A/AA-tagged автоматический скан, не полное доказательство WCAG AA.

Все 16 title отдельно проверены в server HTML. Playwright подтвердил profile/appearance/preferences success status, очистку старого сообщения при редактировании, переключатели с клавиатуры, title при client navigation/back/forward, Ctrl+K focus и Escape. HTTP-ответы тестовые; реальные профильные данные этим прогоном не изменялись.

Тёмная тема: дополнительно шесть снимков profile/settings/semester на 1440/320, без violations/page errors/overflow. Исправлены жёсткий тёмный цвет имени в sidebar и пограничный indigo contrast выбранного элемента. Остальные темы/акценты и все заполненные процессы этим повтором не объявляются полностью проверенными. Screen reader/полная AA-проверка остаются открытыми.
