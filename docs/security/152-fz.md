# Безопасность и 152-ФЗ

> **Рабочий checklist, не заключение о соответствии закону.** Таблицы ниже содержат требования и целевые меры, а не подтверждение реализации. Проверьте фактические code/config controls с ответственным за ПДн и профильным юристом перед заявлением о compliance или публикацией пользовательских текстов. Заполните [privacy policy](../legal/privacy_policy.md) и [terms](../legal/terms_of_service.md) только после проверки оператора, целей, сроков и обработчиков.

## Обзор

Контрольный список для анализа обработки персональных данных; проектное состояние и остаточные риски — в [threat model](threat-model.md).

## Чувствительные данные

| Тип данных | Уровень | Доступ |
|------------|---------|--------|
| ФИО, контактные данные | Обычные | Ролевая модель |
| Принадлежность к вузу/группе | Обычные | Ролевая модель |
| Данные о посещаемости | Повышенный | Куратор, декан, admin |
| Причины отсутствий (здоровье) | **Особый** | Только куратор + студент |
| Загруженные файлы | Обычные | Пространство пары |
| Device tokens | Обычные | Только свой |

---

## Принципы

1. **Минимизация данных** — собираем только необходимое
2. **Прозрачность** — пользователь понимает, что и зачем собирается
3. **Ограничение доступа** — ролевая модель + least privilege
4. **Защита при передаче и хранении** — HTTPS, шифрование
5. **Удаление / экспорт** — право пользователя на удаление и экспорт данных

---

## Организационные требования

- [ ] Политика обработки ПДн опубликована
- [ ] Пользовательское соглашение опубликовано
- [ ] Согласие на обработку ПДн при регистрации (обязательный чекбокс)
- [ ] Отдельное согласие на данные о здоровье
- [ ] Назначен ответственный за обработку данных

---

## Технические требования

| Требование | Реализация |
|------------|------------|
| HTTPS everywhere | TLS 1.3, HSTS |
| Пароли | Backend использует bcrypt; сверяйте настройки в auth source |
| JWT | Access (15–30 мин) + refresh (30–60 дней) |
| Шифрование | AES-256-GCM используется для Moodle token при заданном `CONNECTOR_ENCRYPTION_KEY`; не заявляйте шифрование остальных полей без отдельной реализации |
| Разграничение доступа | Guards в NestJS |
| Логи | Без лишних ПДн |
| Бэкапы | Ежедневные, зашифрованные |
| Удаление аккаунта | Soft-delete + 30 дней |

---

## Доступ к данным об отсутствиях

| Роль | Что видит |
|------|-----------|
| Студент | Только свои статусы |
| Куратор | Статусы своей группы + причины |
| Преподаватель | Факт отсутствия на своей паре (без причины) |
| Админы | По необходимости + с аудитом |

---

## Аудит

Логировать:
- Вход в систему
- Смену ролей
- Загрузку расписания
- Подтверждение / отклонение отсутствий
- Удаление данных

Хранить audit-логи отдельно, 1 год.

---

## Чек-лист 152-ФЗ для пилота

- [ ] Есть политика обработки ПДн
- [ ] Есть согласие пользователя
- [ ] Данные хранятся на территории РФ
- [ ] Реализованы меры защиты
- [ ] Есть базовая процедура реагирования на инциденты
- [ ] Пользователь может запросить информацию о своих данных и удаление
- [ ] Уведомление в Роскомнадзор подано
- [ ] Ответственный за ПДн назначен
- [ ] Договоры с обработчиками заключены
