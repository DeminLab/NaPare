# Бизнес-проверки изоляции вузов — 25 октября 2026

Проверки для ревьюера backend. Дополняют [матрицу маршрутов](tenant-isolation.md) и guard probes фактическим выполнением JWT → HTTP → controller/service → PostgreSQL. Это не проверка production и не подтверждение всех 375 объявлений маршрутов.

## Как устроена проверка

Используется [tenant-isolation.e2e-spec.ts](../../apps/backend/test/tenant-isolation.e2e-spec.ts) с настоящим AppModule, ValidationPipe, двумя вузами и NOSUPERUSER/NOBYPASSRLS. База должна быть новой локальной `curation_test_*`; существующие рабочие данные не используются. Вуз Б содержит настоящие связанные группу, студента, преподавателя, курс, серию/занятие, пространства, событие, отсутствие и личные уведомления. Администраторы обоих вузов получают собственные кураторские назначения через HTTP.

Перед отрицательным вызовом тот же метод успешно выполняется актёром Б. Для изменяющих методов создаётся отдельная копия ресурса Б: успешный DELETE не уничтожает объект, на котором проверяется чужой запрос. Тела POST/PATCH проходят настоящую DTO-валидацию. Результат 400 не засчитывается как защита вуза.

После положительного контроля фиксируется снимок всех зарегистрированных сущностей с `universityId = Б`, а также связанных объявлений, подготовок/homeworks, метаданных файлов, обсуждений и подтверждений отсутствий. После чужого запроса снимок должен совпасть, включая число строк и поля. Настоящий async notification handler выполняется через делегирующий spy; перед снимком ожидается завершение его Promise. Генерация уведомлений от положительного контроля не скрывается исключением таблиц и не подменяется пустым ответом.

## Что выполняется

| Семейство | Настоящие обработчики и утверждения |
| --- | --- |
| Расписание | Чтение занятия/изменений, PATCH/DELETE; запрет смены вуза и чужих groupId/teacherId |
| Academic | Курс/пространство/серия, context/space/changes occurrence, PATCH курса/occurrence, создание occurrence; списки курсов/occurrences/events и фильтры по группе Б; запрет чужих ссылок при создании серии/события |
| Pair space | Список пространств группы, пространство/timeline/messages/personal-note; PUT заметки, POST сообщения/объявления/homework/метаданных файла. Загрузка байтов и обращение к URL файла не выполняются |
| Администрирование | Роли/status/reset-password, факультет/группа; списки пользователей/факультетов/групп и студентов группы Б |
| Кураторство | Студенты/занятия/кураторы группы, context отсутствия, доступные группы и кандидаты |
| Отсутствия/посещаемость | Чтение отсутствий и посещаемости занятия; PATCH/DELETE/confirm/excuse; POST посещаемости с корректными вложенными studentId/status |
| Личные данные | GET users/:id: сначала собственный профиль Б, затем запрет другому аккаунту. Личные notifications/inbox lists, read/complete/snooze и неизменность записей Б |

Два endpoint `GET /absences/student/:studentId` и `/absences/stats/:studentId` сохраняют существующий контракт: для недоступного студента возвращаются пустая страница или `{total:0,byType:{}}`. Контроль Б обязан показать непустой результат; актёр А — ровно пустой, без изменения БД. Аналогично идемпотентный inbox complete может вернуть 200 при отсутствии доступной строки; само отсутствие изменений обязательно проверяется в БД.

## Границы результата

### Дополнение: Pair Space и скрытый родитель homework

Настоящий homework Б создаётся через POST до отрицательных проверок. Новые PATCH progress/submit сначала выполняются студентом Б (создание и обновление), затем студентом А по тому же homework ID. Снимки дополнительно включают `homework_progress` и `homework_submissions` через join homework → pair_space: отсутствие собственного universityId у дочерней таблицы не исключает её из проверки.

Первый прогон воспроизвёл четыре 500 на чужих PATCH при успешных контролях Б. Проверка области разыменовывала недоступный joined parent. Исправление `assertRoleScopedAccess` возвращает 404 при отсутствии пространства до чтения universityId. Это исправление ошибочного ответа 500 → 404; URL/DTO и успешные ответы своего вуза сохраняются. Таблица ниже описывает выбранные HTTP-сценарии, не все роли/состояния.

| Маршрут pair-spaces | Контроль |
| --- | --- |
| GET groups/:groupId | Пространство группы Б доступно администратору Б, не А |
| GET :lessonId | Существующее пространство/материалы Б доступны Б, не А |
| GET :lessonId/timeline | Контекст предмета доступен Б, не А |
| POST :lessonId/announcements | Разрешённая запись Б в отдельную копию; А не пишет в исходное пространство Б |
| POST :lessonId/homeworks | Создание Б успешно; чужая запись А запрещена |
| POST :lessonId/files | Сохраняются только синтетические metadata; байты/внешние URL не загружаются |
| GET :lessonId/messages | Доступ к обсуждению требует доступного занятия |
| GET :lessonId/personal-note | Свой доступ Б успешен; А не читает заметку чужого занятия |
| PUT :lessonId/personal-note | Б сохраняет личную заметку; А не пишет в занятие Б |
| POST :lessonId/messages | Б пишет обсуждение; А не пишет в занятие Б |
| PATCH homeworks/:id/progress | Личный checklist Б создаётся/обновляется; чужой homework для А даёт отказ без строк |
| PATCH homeworks/:id/submit | Существующий legacy API Б создаёт/обновляет submission; А получает отказ без строк |

Legacy submit проверяется как существующий серверный контракт; новый студенческий workflow сдачи не вводится, Moodle и реальные файлы не вызываются. Итог исправленного прогона/CI фиксируется отдельно: исходные четыре 500 не считаются успешной изоляционной проверкой.

Исправленный локальный прогон: 92 HTTP/PostgreSQL passed, включая все четыре новых create/update случая; 32 существующих unit-теста service/controller Pair Space, backend typecheck, root lint/docs lint, AI/boundary guards и inventory375 passed. Проверены отказы 403/404 и неизменность данных обоих вузов, включая связанные progress/submission строки. PR/CI/интеграция этого исправления фиксируются отдельно от результатов PR 28/32.

### Матрица academic: 15 объявленных маршрутов

Расширение suite добавляет положительное создание в Б и отрицательные попытки А для faculty/course/group/teacher/occurrence references. У отрицательных create/PATCH дополнительно сравниваются снимки **обоих** вузов: ошибка не должна оставить частичную запись в А. Создание курса с одинаковым code в двух вузах и события без связей проверяет область из JWT и неизменность Б при допустимой записи А.

| Маршрут academic | Положительный контроль и межвузовая проверка |
| --- | --- |
| GET courses | Список Б содержит его курс; список А его не содержит |
| POST courses | Отдельные курсы с одним code в своих вузах; чужой facultyId отклонён без частичных строк |
| GET courses/:id | Б читает существующий курс; А получает отказ |
| PATCH courses/:id | Б изменяет отдельную копию; А не меняет курс Б; чужой facultyId для своего курса запрещён |
| GET courses/:courseId/space | Созданное пространство Б доступно Б, не А |
| GET courses/:courseId/series | Список серий своего курса читается Б, не А |
| POST courses/:courseId/series | Б создаёт серию; А не создаёт её под курсом Б и не связывает свой курс с groupId/teacherId Б |
| GET occurrences | Наличие занятия Б только у Б, включая фильтр по его группе |
| GET occurrences/:id/context | Связанные course/series/occurrence доступны Б, не А |
| GET occurrences/:id/space | Настоящее связанное пространство существует и читается Б, не А |
| POST series/:seriesId/occurrences | Б создаёт occurrence под отдельной серией; А не пишет в существующую серию Б |
| PATCH occurrences/:id | Б изменяет копию; исходное занятие/история Б не меняются от запроса А |
| GET occurrences/:id/changes | История читается в контексте Б; А не получает чужую |
| GET events | Событие Б исключено из списка А, включая чужой groupId filter |
| POST events | События без ссылок получают вуз из JWT; чужие courseId/groupId/occurrenceId отклоняются без строк в обоих вузах |

Матрица описывает конкретные сценарии tenant boundary для 15 объявлений AcademicController, а не все возможные роли, состояния и комбинации полей. Окончательный результат расширенного suite фиксируется в журнале/CI; остальные семейства остаются отдельными.

Промежуточное расширение после PR 28 прошло 77 HTTP/PG сценариев; дополнительные десять охватывают academic create/reference scope. Затем добавлены проверки schedule ниже. Прежние 67 сценариев PR 28 остаются отдельным историческим результатом.

### Матрица schedule: 9 объявленных маршрутов

| Маршрут schedule | Положительный контроль и межвузовая проверка |
| --- | --- |
| GET my | Администратор Б видит занятие Б за заданный период; А не получает его |
| GET / | Дата, groupId и teacherId проверяются отдельными HTTP-вызовами: занятие Б есть только у Б |

| GET changes | В fixture действительно есть changed-занятие Б; А его не получает |
| POST / | Вуз из тела не подменяет JWT scope; чужие groupId/teacherId отклонены без частичных строк в обоих вузах |
| PATCH :id | Б изменяет отдельную копию, А не меняет занятие Б; перенос вуза и чужие ссылки запрещены |

Матрица schedule проверяет университетских администраторов. Отдельные сценарии выполняют GET date/my/range студентами и преподавателями обоих вузов; для date передаются чужие groupId/teacherId, которые не должны заменять собственную область актёра. Используются внутренние UUID групп; legacy numeric/SIBIT ветка, платформенные сценарии и внешние коннекторы из этого контроля не выводятся. Это не полный P0-1.
