# Бизнес-проверки изоляции вузов — 25 октября 2026

Проверки для ревьюера backend. Дополняют [матрицу маршрутов](tenant-isolation.md) и guard probes фактическим выполнением JWT → HTTP → controller/service → PostgreSQL. Это не проверка production и не подтверждение всех 375 объявлений маршрутов.

## Как устроена проверка

Используется [tenant-isolation.e2e-spec.ts](../../apps/backend/test/tenant-isolation.e2e-spec.ts) с настоящим AppModule, ValidationPipe, двумя вузами и NOSUPERUSER/NOBYPASSRLS. База должна быть новой локальной `curation_test_*`; существующие рабочие данные не используются. Вуз Б содержит настоящие связанные группу, студента, преподавателя, курс, серию/занятие, пространства, событие, отсутствие и личные уведомления. Администраторы обоих вузов получают собственные кураторские назначения через HTTP.

Перед отрицательным вызовом тот же метод успешно выполняется актёром Б. Для изменяющих методов создаётся отдельная копия ресурса Б: успешный DELETE не уничтожает объект, на котором проверяется чужой запрос. Тела POST/PATCH проходят настоящую DTO-валидацию. Результат 400 не засчитывается как защита вуза.

После положительного контроля фиксируется снимок всех зарегистрированных сущностей с `universityId = Б`, а также связанных объявлений, подготовок/homeworks, метаданных файлов, обсуждений и подтверждений отсутствий. После чужого запроса снимок должен совпасть, включая число строк и поля. Настоящий async notification handler выполняется через делегирующий spy; перед снимком ожидается завершение его Promise. Генерация уведомлений от положительного контроля не скрывается исключением таблиц и не подменяется пустым ответом.

## Что выполняется

| Семейство | Настоящие обработчики и утверждения |
| --- | --- |
| Расписание | Чтение занятия/изменений, PATCH/DELETE; запрет смены вуза и чужих groupId/teacherId |
| Academic | Курс/пространство/серия, context/space/changes occurrence, PATCH курса/occurrence, создание occurrence; списки курсов/occurrences/events и фильтры по группе Б; запрет чужих ссылок при создании серии/события |
| Pair space | Список пространств группы, пространство/timeline/messages/personal-note; PUT заметки, POST сообщения/объявления/homework/метаданных файла. Загрузка байтов и обращение к URL файла не выполняются |
| Администрирование | Роли/status/reset-password, факультет/группа; списки пользователей/факультетов/групп и студентов группы Б |
| Кураторство | Студенты/занятия/кураторы группы, context отсутствия, доступные группы и кандидаты |
| Отсутствия/посещаемость | Чтение отсутствий и посещаемости занятия; PATCH/DELETE/confirm/excuse; POST посещаемости с корректными вложенными studentId/status |
| Личные данные | GET users/:id: сначала собственный профиль Б, затем запрет другому аккаунту. Личные notifications/inbox lists, read/complete/snooze и неизменность записей Б |

Два endpoint `GET /absences/student/:studentId` и `/absences/stats/:studentId` сохраняют существующий контракт: для недоступного студента возвращаются пустая страница или `{total:0,byType:{}}`. Контроль Б обязан показать непустой результат; актёр А — ровно пустой, без изменения БД. Аналогично идемпотентный inbox complete может вернуть 200 при отсутствии доступной строки; само отсутствие изменений обязательно проверяется в БД.

## Границы результата

25 октября локально прошли все 67 HTTP/PostgreSQL сценариев этого suite, backend typecheck, root lint/docs lint, AI/boundary guards, inventory375 и проверка локальных ссылок. Это число сценариев, а не число уникальных маршрутов. PR/CI и включение в интеграцию ещё проверяются отдельно.

Окончательные число сценариев, PR и CI фиксируются в [журнале выполнения](../project-log/improvement-progress-2026-10-22.md). Эта серия усиливает существующий учебный HTTP suite; отдельные suites офисных запросов/отчётов, платформенных grants, карьеры, платежей, экспорта/удаления, аналитики и WebPush остаются самостоятельными доказательствами.

Наличие guard probe, строки в AST-инвентаризации или успешного запроса одного семейства не закрывает остальные бизнес-маршруты. Для полного P0-1 ещё требуется сверка всех маршрутов с конкретными положительными/отрицательными бизнес-сценариями; текущий документ не заявляет такого покрытия. Внешние Moodle/СИБИТ, банк, push provider, устройства и production этим suite не вызываются.
