# Sprint Playbook

## Формат

- **Длительность спринта:** 2 недели
- **Старт:** понедельник
- **Ретро:** пятница (30 мин)
- **Планирование:** понедельник (1 час)

---

## Ритуалы

| Ритуал | Когда | Время | Цель |
|--------|-------|-------|------|
| Sprint Planning | Пн, начало спринта | 1 час | Определить задачи |
| Daily Standup | Ежедневно | 5 мин | Статус, блокеры |
| Sprint Review | Пт, конец спринта | 30 мин | Демо результата |
| Sprint Retro | Пт, конец спринта | 30 мин | Что улучшить |

---

## Приоритизация

Используем **RICE** для оценки задач:

| Фактор | Описание |
|--------|----------|
| Reach | Сколько пользователей затронет |
| Impact | Насколько сильно улучшит (1–3) |
| Confidence | Уверенность в оценке (100/80/50%) |
| Effort | Сколько времени (дни) |

**RICE = (Reach × Impact × Confidence) / Effort**

---

## Бэклап

Бэклап ведётся в GitHub Issues / Projects.

### Статусы

| Статус | Описание |
|--------|----------|
| Backlog | Не оценено |
| Ready | Оценено, можно брать |
| In Progress | В работе |
| In Review | PR отправлен |
| Done | Задеплоено на staging |
| Shipped | На production |

---

## Definition of Ready (DoR)

Задача готова к взятию в спринт, когда:

- [ ] Описана пользовательская история / задача
- [ ] Есть критерии приёмки
- [ ] Есть дизайн / макет (если UI)
- [ ] Есть API-контракт (если backend)
- [ ] Оценка по RICE
- [ ] Нет зависимостей от заблокированных задач
