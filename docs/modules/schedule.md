# Module: Schedule (Расписание)

> API/data-flow details below describe the repository implementation where linked to current sources. UX/NFR/acceptance checklists and TODOs are goals; they do not prove runtime uptime, push delivery or measured performance.

## 1. Цель и границы

**Цель:** Надёжное получение, хранение, обновление и отображение расписания + детект изменений.

**Не делает:** Публикация контента в пространство пары (pair-space), уведомления (notifications).

## 5. UX / экраны

- Экран расписания (student) — [ui/screens-student.md](../ui/screens-student.md)
- Страница `/groups` использует существующий публичный каталог и расписание СИБИТ из `rasp.sano.ru`: студент может выбрать группу и учебный год, синхронизировать избранные группы с аккаунтом, просматривать неделю и искать по предмету, преподавателю или аудитории. Ранее сохранённые локальные группы объединяются с серверным списком при первом онлайн-входе; офлайн-изменения избранного ставятся в локальную очередь и отправляются после восстановления соединения. Выбранное публичное расписание сохраняется локально и сразу показывается при повторном открытии, пока идёт фоновое обновление; при сетевой ошибке остаётся доступна копия с отметкой времени. Внешние занятия остаются только для просмотра и не открывают локальный Pair Space.
- Месячный календарь студента — `/month`; получает весь role-scoped диапазон через `/schedule/range`, сохраняет его локально по аккаунту и показывает месячную сетку на больших экранах и список дней на мобильных. Текущий месяц можно скачать в `.ics` вместе с предметом, временем, преподавателем, корпусом/аудиторией и описанием изменения.
- Экран расписания (teacher) — [ui/screens-teacher.md](../ui/screens-teacher.md)
- A02. Админка: загрузка расписания — [ui/screens-admin.md](../ui/screens-admin.md)

**Критичные UX-требования:**

- При недоступности источника — последнее валидное расписание с предупреждением
- Индикатор «Изменено» при наличии LessonChange
- Pull-to-refresh
- Тип занятия во всех расписаниях обозначается общей текстовой меткой и цветом: лекция — синий, практика — зелёный, лабораторная — янтарный; остальные типы остаются нейтральными. Цвета используют общие токены с контрастными значениями для системной тёмной темы.
- Студенческие экраны «Сегодня», неделя и месяц показывают корпус, аудиторию, подгруппу и нечётность/чётность, если источник передал эти поля. У СИБИТа источник уже отдаёт конкретные даты занятий и `weekType`; NaPare показывает этот признак и строит календарь по датам источника. Личные недельные экраны студента и преподавателя, а также групповые недельные обзоры охватывают понедельник–воскресенье и строят API-диапазоны по локальной календарной дате; личный студенческий экран группирует занятия по `startDate`, открывает нужную неделю по `?date=YYYY-MM-DD` из уведомлений, поддерживает быстрый поиск и фильтры для лекций, практик, лабораторных, экзаменов, консультаций, курсовых и зачётов; преподавателей можно добавить в серверное избранное аккаунта и фильтровать неделю по ним. Отдельную пару (кроме отменённых) можно открыть в Google Calendar с предметом, временем, местом и преподавателем; выбранную неделю и месяц можно скачать в `.ics` для импорта в Google Calendar, Apple Calendar и другие приложения. Отменённые занятия исключены из обоих экспортов. Это разовые добавления и снимки, не автоматическая подписка. Кэш недели и месяца привязан к аккаунту, показывается сразу и обновляется в фоне; при ошибке сети видна последняя сохранённая версия с датой.
- В Pair Space студент видит сохранённые записи истории расписания со старым и новым временем, аудиторией, предметом и преподавателем.

## 6. Бизнес-правила и edge-cases

Персональный экран «Мой день» передаёт диапазон локального календарного дня как UTC timestamps. Для `findForStudentDateRange` необязательный IANA `timeZone` применяется к ключам дат внешнего расписания СИБИТа; без него сохраняется прежняя обработка date-only значений. Диапазонные запросы к сохранённым занятиям остаются ограничены переданными UTC-границами и существующими tenant/role-фильтрами.

1. **Детект изменений:** сравнение при каждой загрузке → LessonChange (moved, cancelled, room_changed, teacher_changed, added)
2. **Чётность недели:** для датированных записей поддерживается отображение upstream `weekType` (`odd`/`even`/`both`); импорт и персональные запросы используют реальные даты СИБИТа. Генерация будущих занятий из академических повторяющихся серий по `weekType` пока не реализована: для неё нужны опорная дата семестра и генератор `LessonOccurrence`.
3. **Каникулы (не реализовано end-to-end):** для скрытия занятий нужен календарь периодов семестра/каникул, связанный с расписанием. Сейчас такой календарь не применяется к выдаче `/schedule/range`.
4. **Конфликты:** две пары в одно время для одной группы → алерт в админке
5. **Синк СИБИТа:** ручной `POST /admin/schedule/sync` создаёт факультеты и группы с `externalId`, связывает ранее зарегистрированного студента с его локальной группой и сохраняет уроки с `source=sibit`. Повторный синк обновляет только такие уроки по паре `externalId + groupId`; ручные записи ВУЗа не перезаписываются. Пока JWT старого студента содержит числовой внешний ID, чтение расписания резолвит его к импортированной группе и всё равно возвращает сохранённые UUID уроков.
6. **Идемпотентность:** повторная загрузка не дублирует данные
7. **Тип изменения:** ручное изменение сохраняет старые/новые значения для предмета, начала/окончания, корпуса/аудитории и преподавателя. История различает перенос даты/времени, смену места, смену преподавателя и прочее обновление. Изменение даты, времени или корпуса формирует соответствующий schedule event с предметом и парой старых/новых значений; уведомление адресуется студентам группы и преподавателю и ведёт в пространство пары.
8. **Изменения источника:** детектор сравнивает дату, время, аудиторию, корпус, преподавателя, предмет, тип занятия, подгруппу и чётность недели; история хранит изменённые значения до и после. Краткое описание показывает пары значений (например, `Аудитория: 302 → 511`). Событие несёт поля diff, группу и преподавателя; обработчик уведомлений адресует его студентам группы и преподавателю. Уведомление ведёт в пространство изменившейся пары.
9. **Откат:** возможность вернуть предыдущую версию расписания
10. **Коннекторы:** см. [architecture/connectors.md](../architecture/connectors.md)

## 7. События и уведомления

| Событие                        | Тип уведомления    | Получатель                     |
| ------------------------------ | ------------------ | ------------------------------ |
| Изменение расписания           | In-app notification/event stream where a schedule event is produced; no FCM/APNs push | Студенты группы, преподаватель |
| Недоступность коннектора > 24ч | Target alert policy; no automatic alert is established by this module guide | university_admin |
| Новая пара                     | In-app event where emitted; no system push delivery | Студенты группы |

## 8. Нефункциональные требования

| Требование  | Значение                          |
| ----------- | --------------------------------- |
| Latency     | p95 ≤ 300 мс для GET /schedule/my |
| Offline     | Просмотренные неделя и месяц хранятся локально отдельно для аккаунта; детали пары и остальные экраны требуют сети |
| Rate limits | Upload quota of 1/hour per university is a target in this document; not confirmed in the current controller. |

## 9. Критерии приёмки

- [ ] Можно загрузить расписание СИБИТ через файл и увидеть у студентов
- [ ] При повторной загрузке система корректно определяет типы изменений
- [ ] Студент получает уведомление об изменении
- [ ] При недоступности источника показывается последнее расписание с предупреждением
- [ ] Конфликты расписания детектятся
- [ ] Чередование недель работает
- [ ] Каникулы отображаются корректно

## Date range boundaries

Date-only end dates include the entire final UTC day for stored lessons. ISO timestamps remain exact. The existing IANA timezone parameter continues to govern date-only external student schedules.
