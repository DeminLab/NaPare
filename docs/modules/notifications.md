# Module: Notifications (Уведомления)

## 1. Цель и границы

**Цель:** Надёжно и вовремя сообщать пользователям о важных событиях через push (FCM + APNs) и in-app.

**Не делает:** Бизнес-логику (только реагирует на события из других модулей).

---

## 2. Сущности

| Сущность | Описание | Ключевые поля |
|----------|----------|---------------|
| Notification | Уведомление | id, user_id, type, title, body, deep_link, is_read |
| DeviceToken | Токен устройства | id, user_id, platform, token |

Подробнее: [architecture/data-model.md](../architecture/data-model.md).

---

## 3. API

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/api/v1/notifications` | GET | Список уведомлений |
| `/api/v1/notifications/{id}/read` | PATCH | Отметить прочитанным |
| `/api/v1/notifications/read-all` | POST | Отметить все прочитанными |
| `/api/v1/devices/token` | POST | Зарегистрировать/обновить token |
| `/api/v1/notifications/settings` | GET | Настройки уведомлений |
| `/api/v1/notifications/settings` | PATCH | Обновить настройки |

Полный OpenAPI: [api/README.md](../api/README.md).

## 6. Бизнес-правила и edge-cases

**Типы уведомлений (MVP):**

| Событие | Текст (пример) | Получатель |
|---------|----------------|------------|
| Изменение расписания | «Пара "Программирование" перенесена на 14:00» | Студенты, преподаватель |
| Новое объявление | «Новое объявление в паре "Математика"» | Студенты группы |
| Новое ДЗ | «Новое задание: Лабораторная №3 (дедлайн 10.09)» | Студенты группы |
| Новый файл | «Преподаватель загрузил файл в "Физика"» | Студенты группы |
| Дедлайн | «Завтра дедлайн: Лабораторная №3» | Студент |
| Решение по отсутствию | «Куратор подтвердил ваш статус "Болен"» | Студент |
| Новое отсутствие | «Иванов А. установил статус "Болен"» | Куратор |

**Антиспам:**
- Группировка при массовых изменениях расписания
- «Тихие часы» (желательно, можно отложить)
- Настройки по типам событий

**Техническая реализация:**
```
Бизнес-событие → Event Bus → Notification Service → создание записи + отправка push → лог доставки
```

## 7. События и уведомления

Модуль **потребляет** события из других модулей:
- schedule: lesson_change
- pair-space: announcement_created, homework_created, file_uploaded
- absences: absence_created, absence_confirmed, absence_rejected

---

## 8. Нефункциональные требования

| Требование | Значение |
|------------|----------|
| Push delivery | ≤ 3 секунды |
| Retry | 3 попытки при временных сбоях |
| История | 30–60 дней |
| Часовые пояса | Учёт при отправке |

---

## 9. Критерии приёмки

- [ ] При изменении расписания студент получает push
- [ ] При публикации ДЗ / файла / объявления приходит уведомление
- [ ] Нажатие на уведомление открывает правильный экран
- [ ] Пользователь может отключить отдельные типы
- [ ] Куратор получает уведомление о новом отсутствии
- [ ] Нет массового спама
- [ ] Push работает на iOS и Android
