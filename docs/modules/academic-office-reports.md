# Отчёты учебного офиса

Текущая реализация ветки `codex/p1-office-reports`, 24 октября 2026. Читатели: администратор вуза, учебный офис, декан и сопровождающий интеграции. Реальные источники и production не проверены.

Экран `/deanery/requests/reports` открывается из содержимого страницы заявлений. Общие navigation/header/Avatar/logo и student-приложение не изменяются.

## Контингент и права

Считаются текущие активные аккаунты с основной ролью student и однозначной группой своего вуза. Поддерживаются UUID группы и legacy external ID; неоднозначные совпадения не распределяются предположительно. Администратор без фильтров видит число нераспределённых аккаунтов, scoped сотрудник не получает этот общевузовский остаток. Это контингент платформы, не официальный реестр приказов о зачислении/отчислении и не историческая статистика.

Отчёты читает администратор своего вуза, действующий учебный офис назначенных групп/факультетов или действующий декан своего факультета. Диспетчер, методист и куратор не получают этот отчёт автоматически. Загрузить реестр может только администратор своего вуза. Прежний endpoint долгов конкретного студента сохраняет self/office/curator/dean модель доступа. Назначения проверяются на каждой операции; чужие group/faculty IDs недоступны, параметр universityId не принимается. FORCE RLS защищает вуз, сервис дополнительно ограничивает подразделение.

Ответы private/no-store. Смена сессии в другой вкладке очищает экран/форму и требует перезагрузки. CSV-кнопки скачивают только обозначенную текущую страницу с защитой ячеек от spreadsheet formula injection. Это не XLSX и не скрытая выгрузка всех страниц.

## Подтвердить официальный источник

Дополнительный путь загрузки реестра не интерпретирует оценки Moodle как долги. Программа проверяет принадлежность и целостность загрузки; официальный статус и полноту списка подтверждает администратор. Независимая проверка подлинности документа и полномочий его составителя не выполняется.

1. Получите разрешённый полный список задолженностей **одной группы** на дату UTC. Используйте точные UUID студенческих аккаунтов платформы из существующего администрирования. Сопоставление по ФИО не выполняется.
2. Подготовьте UTF-8 JSON-массив до 2000 объектов: studentId, subject, period, basis. Браузер допускает файл до 2,5 МБ, сервер — JSON до 3 МБ. Превышение лимита отклоняется целиком; частичный список нельзя выдавать за полный.
3. Выберите группу, название источника, реквизиты и дату. Не вносите имена, контакты, медицинские сведения, секреты и ссылки на частные файлы.
4. Подтвердите официальный источник и полноту списка всей группы. Нажмите «Сохранить подтверждённый реестр». До этого файл не отправляется.
5. Проверьте дату источника и результат. При обрыве связи сохранение может быть не подтверждено: сначала обновите отчёт. Повтор неизменённой формы использует тот же request ID.

Пример формы записи с **синтетическим UUID**, который заменяется точным кодом студента выбранной группы:

```json
[
  {
    "studentId": "11111111-1111-4111-8111-111111111111",
    "subject": "Математика",
    "period": "2026, осенний семестр",
    "basis": "Запись официального реестра"
  }
]
```

Массив [] — явное подтверждение полного пустого реестра группы на дату источника. Без источника available=false и records=[] не означают отсутствие долгов. После подтверждённого пустого снимка available=true, records=[]; более поздние изменения не проверены.

## История, данные и целостность

Миграция 42 добавляет office_debt_snapshots и office_debt_records, внешние ключи, уникальный текущий снимок группы, FORCE RLS и active-writer triggers. Разрушительный rollback запрещён. Новый полный снимок атомарно заменяет прежний текущий, сохраняя историю. Более ранняя дата не может заменить позднюю. Повтор request ID с тем же нормализованным содержимым возвращает прежний результат, с другим — 409. Импорты сериализуются advisory lock своего вуза; аудит содержит группу, дату и число строк без полного реестра.

Дубли студента/дисциплины/периода, чужие, неактивные и находящиеся в другой/неоднозначной группе студенты отклоняются. Отчёт читает только текущие снимки и активных студентов, всё ещё однозначно принадлежащих той же группе. Переведённый студент не раскрывает новому офису прежний реестр. Автоматического переноса/пересчёта источника нет.

Снимок хранит вуз, группу, request ID/digest, источник/реквизиты/дату, код подтвердившего администратора и даты создания/замены. Строка хранит код студента, дисциплину, период и основание. Отдельных колонок имени/контактов нет.

Собственный JSON export включает свои строки всех снимков и прежнего вуза. Администратор получает собственную историю подтверждений без чужих строк. После удаления аккаунта учебная история и подтверждения сохраняются под архивным кодом по утверждённой модели. Реквизиты и основания могут содержать остаточные ПД; сроки, основания хранения и дополнительная очистка требуют оператора. Это псевдонимизация, не необратимое обезличивание.

## API и проверки

| Метод | Назначение |
| --- | --- |
| GET /requests/reports/contingent | Агрегаты текущих групп и source coverage |
| GET /requests/reports/debts | Записи текущих снимков с SQL count/pagination |
| POST /requests/reports/debt-snapshots | Атомарное подтверждение полного реестра группы |
| GET /requests/students/:studentId/debts | Прежний scoped endpoint с подтверждённым источником |

GET-фильтры: groupId, facultyId, page, limit (1–100). Total относится ко всему фильтру, data — к указанной странице.

Уточнение прежнего student-debts endpoint: чужой или отсутствующий студент теперь даёт 404 вместо прежнего 400; синтаксически неверный UUID по-прежнему даёт 400. Успешный контракт unavailable/records сохраняется. Regression suite заявлений обновляет это конкретное ожидание; положительный контроль второго вуза отдельно доказывает, что отрицательная проверка использует существующего студента.

Локально прошли 11 настоящих JWT/HTTP/PostgreSQL сценариев: положительный контроль другого вуза до чужих запросов, неизменность чужой БД, реальные миграции к пустым feature-таблицам, legacy/неоднозначная группа, 105 строк и две страницы, источник/повтор/история, SQL RLS, own export, отзыв назначения на живом JWT и удаление аккаунта с сохранением учебного архива. Все 46 backend unit suites / 492 tests также прошли.

Дополнительно проверены одновременно отправленный одинаковый импорт, собственный архив прежнего вуза, отдельная история подтвердившего администратора, чужой факультет и JSON больше стандартных 100 КБ (400 по предметной проверке группы, не 413 по размеру). Полный прежний office workflow — 14 HTTP/PostgreSQL сценариев; self export — 5; reviewed guard probes — 4607 для 372 деклараций маршрутов. Guard probes не заменяют предметные проверки всех оставшихся маршрутов.

Browser использовал настоящий локальный Next/Nest/PostgreSQL и синтетические аккаунты/реестр: успешный импорт, чтение источника/даты/записи, неверный код студента с сохранённой формой, полный пустой снимок, 45 строк с пагинацией, CSV текущих 20 строк, клавиатуру, сетевой сбой/retry, смену сессии в другой вкладке и восстановление после reload. Скачанный CSV имеет 21 строку с заголовком; ячейка `=1+1` экранирована апострофом. Четыре ширины 320/768/1024/1440 без горизонтального переполнения; scoped axe по новому содержимому — 0 violations/0 incomplete, page errors — 0. После визуальной проверки мобильный фильтр группы получил полную строку (262 px при viewport 360). Это не полный WCAG AA/NVDA или реальный источник.

БД только новая curation_test_* на loopback, runtime role NOSUPERUSER/NOBYPASSRLS. CI использует отдельный OFFICE_REPORT_TEST_DATABASE_URL; без него suite пропускается. Browser, итоговые проверки, PR/CI и интеграция фиксируются отдельно в [журнале](../project-log/improvement-progress-2026-10-22.md). Реальный источник, полномочия и юридические сроки не подтверждены; внешние тестовые подключения пока не подготовлены, как сообщил пользователь.
