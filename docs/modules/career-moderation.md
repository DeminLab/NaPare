# Модерация карьерных задач и жалобы студентов

Дата: 24 октября 2026. Тип: контракт текущей реализации в отдельной ветке `codex/p2-career-moderation`. Production не изменяется. Документ предназначен разработчику и сотруднику карьерного центра; проверка компании описана отдельно в [контракте ИНН](../integrations/company-registry.md).

## Публикация и исправление

Каждая задача проходит ручное согласование, даже когда автоматические признаки риска отсутствуют. Действующий участник компании отправляет черновик на рассмотрение только при подтверждённом партнёрстве компании и вуза. Сотрудник карьерного центра своего вуза одобряет задачу либо возвращает её с причиной. Активное назначение в рассматриваемой компании запрещает этому сотруднику принимать решение.

Отклонённую версию нельзя повторно отправить без изменения содержимого. `PATCH /career/tasks/:id` принимает полный набор редактируемых условий и `expectedVersion`; менять можно только черновик без откликов и работ. Компания и вуз остаются прежними. Реальное изменение увеличивает `moderationContentVersion`. Решение через новый API также требует актуальную версию: устаревшая форма получает 409.

`career-risk-v1` отмечает слова о предоплате и небезопасных действиях, некорректные сумму/часы, вознаграждение от 100 000 рублей и расчётную ставку от 3 000 рублей в час. Это инженерные пороги для очереди, не рыночная оценка и не доказательство мошенничества. Отрицание не снимает признак: сотрудник читает контекст. Для отклонения и решения по задаче с признаками нужна причина от 10 символов. Некорректные сумму/часы одобрить нельзя.

Старые маршруты публикации и одобрения сохранены. Одобрение без версии допускается только для первоначальной версии без признаков риска; иначе сервер требует новый экран. В содержимом карьерного кабинета сотрудника есть ссылка на `/career/moderation`.

## Жалобы и ограничения

Студент своего вуза может пожаловаться на открытую задачу или задачу, на которую ранее откликнулся. Категории: предоплата, расхождение с условиями, небезопасные требования, другое. Текст — 10–4000 символов; одна открытая жалоба от студента на задачу. Маршрут ограничен тремя обращениями в минуту на IP.

Жалоба сохраняет снимок публичных условий на момент обращения. Само обращение не блокирует компанию или задачу. Сотрудник своего вуза рассматривает жалобу с причиной от 10 символов: подтверждение ограничивает новые отклики и выбор исполнителя; отклонение жалобы оставляет условия задачи прежними. Уже назначенные работы, результаты и оплаты автоматически не отменяются. При существующих откликах или работах возврат в изменяемый черновик запрещён; ограничение остаётся до выяснения условий. Снять ограничение можно отдельным решением по актуальной версии задачи.

Студент видит собственную историю и решения на `/career/complaints`, включая обращение по задаче, уже скрытой из открытого списка. Работодатель не получает приватный текст жалоб. Очередь сотрудника содержит только открытые жалобы его вуза, исходный снимок и текущие условия задачи. Списки имеют пагинацию: по умолчанию 20, максимум 50 записей.

## API

Все маршруты требуют JWT; роль, вуз, назначения и состояние проверяет сервис.

| Метод и путь | Назначение |
| --- | --- |
| `GET /career/moderation/tasks` | Очередь рассматриваемых и ограниченных задач своего вуза |
| `POST /career/moderation/tasks/:id/decision` | `approve`/`reject`, `expectedVersion`, причина |
| `PATCH /career/tasks/:id` | Изменение собственного черновика по версии |
| `POST /career/tasks/:id/complaints` | Собственное обращение студента |
| `GET /career/complaints/my` | Своя история; необязательный `taskId` |
| `GET /career/moderation/complaints` | Открытые обращения своего вуза |
| `POST /career/moderation/complaints/:id/decision` | `uphold`/`dismiss` и причина |

Приватные списки и ответы жалоб имеют `Cache-Control: no-store, private`. Формы не повторяют изменения автоматически после сетевой ошибки; введённый текст сохраняется при отказе. При смене сессии приватные списки очищаются.

## Хранение и атомарность

Миграция 40 добавляет метаданные модерации задачи и `career_task_complaint`. Составной FK связывает задачу с тем же вузом; частичный уникальный индекс исключает повторное открытое обращение. FORCE RLS и четыре restrictive policy обязательны также для владельца таблицы. Откат миграции отказывается уничтожать использованную историю.

Изменения и существующий `AuditLog` записываются одной транзакцией. В аудит не копируется приватный текст жалобы. Мутации сначала блокируют строку задачи; подача отклика также проверяет состояние внутри этой блокировки. Отдельный конкурентный тест проверяет отказ отклика после зафиксированного ограничения.

JSON export включает собственные обращения и собственные действия сотрудника. При удалении аккаунта текст собственных жалоб заменяется отметкой удаления; снимок публичных условий, категория, решение, даты и связь под архивным кодом сохраняются. Причины решений могут содержать персональные сведения, поэтому полное необратимое обезличивание не заявляется. См. [удаление аккаунта](../privacy/account-deletion.md).

Локально прошли 18 unit-сценариев политики риска, полный backend 44 suites / 471 tests и 4542 проверки route guards. Десять JWT/HTTP/PostgreSQL сценариев прошли: FORCE RLS, чужой вуз, конфликт интересов, возврат/исправление/версия, приватность жалоб, ограничение новых действий с сохранением начатой работы, конкурентный отклик, откат при ошибке аудита, составной FK, export и очистка текста при удалении. Проверка ожидания использует реальный PID блокирующей транзакции: текст SQL в pg_stat_activity может обрезаться до имени таблицы. Typecheck backend/portal, root lint/docs/guards, inventory367 и локальные ссылки прошли. [PR 23](https://github.com/DeminLab/NaPare/pull/23), `0ac954b`, прошёл все шесть jobs [CI 122](https://github.com/DeminLab/NaPare/actions/runs/40011683424) и включён в интеграционную ветку.

На ширинах 320/768/1024/1440 переполнения нет. В проверенном основном содержимом axe: 0 violations, 2 incomplete; это не подтверждение полного WCAG AA. Скриншот мобильной очереди просмотрен.
