# Module: Absences (Отсутствия)

## 1. Цель и границы

**Цель:** Учёт отсутствий студентов со статусами и подтверждением куратора.

**Не делает:** Расписание (schedule), уведомления (notifications).

---

## 2. Сущности

| Сущность | Описание | Ключевые поля |
|----------|----------|---------------|
| AbsenceStatus | Статус отсутствия | id, user_id, type, start_date, end_date, comment, is_sensitive |
| AbsenceConfirmation | Подтверждение куратора | id, absence_id, curator_id, status, comment |

Статусы: `learning` (учусь), `sick` (болен), `work` (работа), `other_city` (другой город), `other` (другая причина).

Подробнее: [architecture/data-model.md](../architecture/data-model.md).

---

## 3. API

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/api/v1/absences` | POST | Создать статус отсутствия |
| `/api/v1/absences/my` | GET | Мои статусы |
| `/api/v1/curator/absences` | GET | Дашборд куратора |
| `/api/v1/curator/absences/{id}/confirm` | PATCH | Подтвердить |
| `/api/v1/curator/absences/{id}/reject` | PATCH | Отклонить |

Полный OpenAPI: [api/README.md](../api/README.md).

## 6. Бизнес-правила и edge-cases

1. **Автоматический расчёт:** система определяет какие пары попадают под период
2. **Двойное подтверждение:** статус → куратор подтверждает / отклоняет
3. **Чувствительные данные:** причины болезни — только куратору (не преподавателю)
4. **Изменение/отмена:** студент может изменить или отменить статус
5. **Пересечение периодов:** при пересечении — объединение или конфликт (решение: предупреждение)
6. **История:** все статусы сохраняются, видны в дашборде

## 8. Нефункциональные требования

| Требование | Значение |
|------------|----------|
| Latency | p95 ≤ 300 мс |
| Offline | Кэш последнего статуса |
| Приватность | Причины болезни зашифрованы |

---

## 9. Критерии приёмки

- [ ] Студент ставит статус на период — система корректно считает пары
- [ ] Куратор видит таблицу и может подтверждать
- [ ] Уведомления уходят нужным ролям
- [ ] Данные не светятся лишним людям
- [ ] Редактирование и отмена статуса работают

---

## 10. Зависимости

**Зависит от:** auth (JWT, roles), schedule (для расчёта затронутых пар)
**Зависимость от:** notifications (push куратору и студенту)
