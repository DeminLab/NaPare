# Практика и работа

Статус: первый рабочий контур реализован; проверки выполнены локально. Дата: 13 октября 2026. Страна запуска: Россия. Платёжный провайдер: отсутствует по указанию владельца. Этот документ описывает реализацию, а не production-доступность.

## Аккаунты и права

Учебные роли сохранены. Добавлены primary employer/career_staff/career_admin. Работодатель допускает null universityId и ограничен career/своим профилем/выходом/подключением MAX; legacy academic routes закрываются JwtAuthGuard. requireUniversityId запрещает выполнять запрос к учебным таблицам без вуза. Другие роли обязаны иметь вуз (DB check).

CareerMembership задаёт права career_staff/career_admin в собственном вузе и company_owner/company_member в компании. Учебный сотрудник может работать в центре и компании без второго аккаунта. Кабинет выбирается из разрешённых availableModes. Университетский администратор назначает руководителя, руководитель — специалиста. Владелец компании добавляет существующий рабочий аккаунт по email после ручной проверки его принадлежности сотруднику. Автоматическая проверка владения email и система приглашений ещё не реализованы. Учебные роли через карьерный модуль не изменяются.

## Хранение

Отдельные таблицы: company, membership, partnership, profile, admission, task, application, work, review, portfolio, test, test_attempt и notice с префиксом career_. Внешние ключи защищают ссылки; уникальные ограничения исключают повторный отклик, исполнителя, отзыв и кейс. Миграция 1700000000017 сохраняет учебные записи и добавляет роли/таблицы. Университетские роли нельзя преобразовывать в employer через учебную админку.

## Сценарий

Компания -> заявка на партнёрство -> проверка своего карьерного центра -> черновик задачи -> модерация -> open -> отклики -> выбор -> in_progress -> submitted -> revision либо accepted -> настоящий отзыв -> приватный кейс -> публикация по согласию студента и работодателя.

Центр не может подтверждать свою компанию или модерировать свою задачу. Студент не может подтверждать собственный профиль. Выбор исполнителя и приёмка блокируют запись в транзакции; максимум три активные работы студента контролируется также при назначении. Отклики не дают баллы за выполненную работу.

Профиль студента проверяет центр. Допуск привязан к точному направлению. Центр может подтвердить практику/достижения с основанием или опубликовать тест (3–20 вопросов, 2–6 вариантов). Студент получает только вопросы/варианты без правильных ответов. Сервер проверяет ответы, максимум три попытки за 24 часа; успешный тест создаёт подтверждённый допуск. Профиль должен быть подтверждён. Интерфейс первого контура создаёт тест из трёх вопросов.

Приёмка не создаёт оплаченный статус. Вознаграждение хранится в копейках без вычета комиссии из суммы студента. payment.configured=false, provider=null. Реальные переводы, комиссия, продвижение и платёжные споры не реализованы при пустом провайдере.

## Интерфейс и API

Кабинет находится в существующем web-portal по /career; новые Docker/Nginx приложения не нужны. /career/register — регистрация работодателя. /career/portfolio/[studentId] — публичные согласованные кейсы. Ссылки на направление добавлены в Today студента/сотрудника и dashboard ВУЗа.

API /api/v1/career обслуживает профиль, допуски, компании/партнёрства, членство, задачи, отклики, работы, отзывы, кейсы, тесты и уведомления. OpenAPI генерируется из NestJS DTO/controllers. Все действия имеют серверную проверку владельца, компании, вуза и статуса. Списки первого контура ограничены 100 записями, предел указан в UI. Работодатель видит профессиональный профиль только откликнувшихся, а не ведомости и личные учебные сведения.

CareerNotice доставляет события выбора, сдачи, решения и отзыва на сайте; прочтение ограничено владельцем. Внешние сообщения не отправляются. Полный realtime/напоминания, развитая формула рейтинга, файлы вместо ссылок, отзыв назначения прав и расширенная модерация — следующие этапы, не заявлены как реализованные.

## Telegram

По решению владельца Telegram убран из всех актуальных web-интерфейсов. Delivery flag выключен независимо от сохранённых предпочтений. Telegram webhook не зарегистрирован; auth/telegram/link отвечает 410, status возвращает unavailable. Старые поля/сохранённые привязки не удалены. MAX остаётся отдельным способом входа и не является обязательным для карьеры.

## Черновики ИИ и описание автора — 13 октября 2026

Первый этап ИИ: task draft и portfolio draft через серверный настроенный провайдер; явное согласие и проверка компании/владельца. Без CAREER_AI_BASE_URL/MODEL/API_KEY/PROVIDER_LABEL генерация отключена, ручное оформление доступно. Ограничение: 20 запросов пользователя и 200 всего сервиса за календарные сутки UTC; неудачные внешние запросы тоже учитываются. Лимиты резервируются транзакцией и сохраняются в career_ai_request без текстов.

Миграция 1700000000018 добавляет caseText отдельно от принятого результата и отзыва. Редактирование скрывает кейс; повторная публикация сохраняет проверку согласия работодателя. Публичная страница явно отделяет описание автора от принятого результата. ИИ не сохраняет и не публикует своё предложение.

## Совместимость с учёбой — 13 октября 2026

GET /career/planning и PUT /career/availability доступны только самому студенту. Сохраняются бюджет 1–40 часов на ближайшие 7 дней, IANA timezone, рабочие окна по дням и включительные периоды недоступности. День/время задаются в часовом поясе учебного расписания. Бюджет не назначается платформой автоматически.

План исключает пересечения рабочих окон с каноническими датами и startTime/endTime собственного группового расписания; дубли/подгруппы объединяются консервативно, прошедшее время исключается. Из меньшего значения бюджета и окон до срока резервируется весь заявленный объём активных работ: остаток выполнения неизвестен. За пределы 7 дней оценка не экстраполируется. Дорога, самостоятельная подготовка и актуальность самого источника не гарантируются.

Нет настроек, группы, занятий в источнике или доступного расписания — совместимость unknown, а не обещанное свободное время. Временная оценка fits/tight не изменяет право отклика; обязательны подтверждённый профиль, точный допуск, действующий срок и прежний лимит 3 работ. Весь каталог остаётся доступен для просмотра.

Уровень starter/standard/advanced и requirements указывает работодатель. Уровни информативны, не являются скрытым рейтингом. Чеклист ведёт от профиля к допуску, первой задаче и кейсу по фактическим данным.

CareerAdmission.basis хранит test/center/unspecified. Старые записи остаются unspecified; их основание не угадывается. Работодатель видит только skill+basis для направлений своих задач, на которые студент действительно откликнулся. Достижения/evidence, reason, оценки, посещаемость, расписание и availability не передаются ему или модели.

Миграция 1700000000019 сохраняет прежние данные. Проверки текущего этапа фиксируются в [плане](../product/career-ai-development-plan.md).

## Interface refinement — 14 October 2026

Task catalogue uses compact summaries with expandable requirements, criteria, and fit explanations. Availability settings open in a native modal; the time calculation is collapsed by default. Task creation has three steps and an explicit draft preview. Applicant and profile review use a selected-record queue. Tabs and filters restore from URL. Skill tags preserve the existing array contract. Acceptance criteria appear beside submitted results; published portfolio separates author text, accepted result and employer review. Payments and live AI remain unconfigured.
