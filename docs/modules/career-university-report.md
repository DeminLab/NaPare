# Отчёт карьерного центра вуза

23 октября 2026. Справочник реализации P2-2 в отдельной ветке. Production не изменён. Отчёт показывает задачи, отклики и принятые работы карьерного модуля; официальное трудоустройство и зачёт практики из этих данных не выводятся.

## Экран и права

`/career/reports`, ссылка в содержимом кабинета карьерного центра. На экране: имя вуза, время снимка, период «за всё время», три показателя и разбивка каждого набора по статусам. Есть отдельные состояния загрузки, ошибки, отсутствия задач и готового отчёта. После ошибки обновления прежние данные остаются с прежней датой снимка; при утрате прав/смене аккаунта убираются. XLSX создаётся по новому снимку при нажатии, поэтому его время и числа могут отличаться от ранее открытого экрана.

Права совпадают с существующим `CareerService.center()`: основные `career_staff`, `career_admin`, `university_admin` своего вуза либо действующее дополнительное назначение `career_staff`/`career_admin` в том же вузе. Работодатель и студент без такого назначения не получают отчёт. Доступ разработчика/владельца автоматически не расширяется. Отзыв назначения проверяется сервером при следующем запросе.

## API и смысл показателей

| Маршрут | Результат |
| --- | --- |
| `GET /api/v1/career/center/report` | JSON: `universityId`, `universityName`, `asOf`, `period=all_time`, `tasks`, `applications`, `acceptedWorks`, `byState`, `limitations` |
| `GET /api/v1/career/center/report.xlsx` | Двоичный XLSX с листами «Сводка» и «Статусы», MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`; не более 10 запросов в минуту на tracker существующего ThrottlerGuard |

Оба ответа `Cache-Control: no-store, private`; XLSX также `nosniff`, attachment с фиксированным именем и `X-NaPare-University-Id`. Вуз определяется только `actor.universityId`. Параметр `universityId` не выбирает чужой вуз; маршрут не принимает целевой вуз. JWT guard защищает маршрут, сервис проверяет назначение, PostgreSQL RLS остаётся включённым. Guard matrix описывает только guard, а не заменяет сервисные проверки.

`tasks` — все задачи этого вуза, включая черновики и закрытые. `applications` — все отклики, связанные с этими задачами. `acceptedWorks` — связанные работы, чей текущий статус `accepted`; не сумма всех сданных работ. Отдельные GROUP BY запросы не умножают числа из-за объединения откликов и работ. Снимок read-only `REPEATABLE READ`; нет лимита первой страницы, периода по дате приёмки или обещания официальной статистики занятости. Связанные с архивным аккаунтом записи сохраняются в агрегатах согласно [утверждённой модели удаления](../privacy/account-rights-model.md).

В JSON/XLSX нет ФИО, email, идентификаторов студентов, текстов откликов, решений, работ и учебного досье. Имя/код вуза и агрегированные статусы — единственные организационные данные. ExcelJS записывает имена как строковые значения и числа как числа, не как формулы. Формулоподобное название проверено тестом. В интерфейсе используются русские названия известных статусов, неизвестный статус выводится текстом. При скачивании проверяются MIME, вуз и неизменность сессии; при смене аккаунта файл не предлагается пользователю. Транспорт использует существующий проверенный session helper экрана данных аккаунта с дополнительным режимом raw Response; старый JSON-режим сохранён.

## Фактическая проверка

- 6 настоящих JWT/HTTP/PostgreSQL E2E, свежая loopback БД с NOSUPERUSER/NOBYPASSRLS и миграциями 37–38: 125 своих задач, 250 откликов, 110 принятых работ, чужие записи, неавторизованный/студенческий/работодательский доступ, дополнительное назначение и его отзыв, XLSX и отсутствие персональных полей. После настоящего self-erasure числа сохранены.
- Все backend unit: 42 suites / 430 passed. Guard probes: 4438 passed, инвентаризация 359 маршрутов; это не 359 негативных бизнес-процессов.
- Реальный локальный Next/Nest/PostgreSQL browser: переход из карьерного центра, показатели 3/2/1 и настоящий XLSX с теми же числовыми ячейками, снимок 320 px просмотрен, 320/768/1024/1440 без overflow, 0 `pageerror`. axe-core 4.10.3 для заполненного `main`: 0 violations / 0 incomplete по WCAG 2/2.1 A/AA. Отдельный подменённый 503 подтвердил сохранение предыдущего снимка после ошибки обновления.

Browser-сценарий использует синтетические записи и локальные сервисы. Он не доказывает deployment, production, официальное трудоустройство, оплату или полную ручную доступность. CI запускает suite на отдельной `CAREER_REPORT_TEST_DATABASE_URL`; без переменной локальный suite явно skipped.
