# Упрощение рабочих кабинетов

Реализовано локально 15 октября 2026 года по запросу владельца: улучшить каждую страницу преподавателя, куратора, декана и административной панели по образцу студенческого кабинета. Документ описывает исходный код и локальную проверку, а не состояние продакшена.

## Общий принцип

На первом плане — данные и действия. Инструкции знакомства с кабинетом, повторные названия разделов, декоративные показатели и крупные пустые карточки сокращены. Синий акцент сотрудников и фиолетовый администрации сохранены; стили компактности ограничены `.role-content`. Реализация общей шапки, логотипы, Avatar, серверные контракты и Docker не изменены. Предыдущие изменения студенческого кабинета и портала сохранены.

Преподаватель не получает интерфейс рассмотрения обращений. Фактические права проверяет backend. Источник очереди — существующий `GET /absences/pending`, решения — существующие `PATCH /curator/absences/:id/confirm` и `/reject`. Неуспешное решение сохраняет запись; успешное удаляет её из текущего списка перед обновлением. Уведомление на запись вне текущей страницы сопровождается сообщением и навигацией по страницам: отдельного API чтения обращения по ID не добавлено.

## Проверка

Локально проходят проверки TypeScript обоих приложений, общий lint и защитные проверки репозитория. Браузерная проверка выполняется через Playwright CLI на Next dev-серверах с тестовыми ответами API. Исходный проход покрывает все 23 страницы и варианты куратора/декана на 320, 768, 1024 и 1440 px; отдельные повторные проверки охватывают последние изменения и ширину 390 px.

Проверены переход из события к обращению, обязательность причины отказа, сохранение записи после ошибки API, обновление очереди после решений, состояние недоступности для преподавателя, фильтр заблокированных пользователей, отправка только изменённой отметки посещаемости и открытие формы подготовки из нового меню.

Итог: 136 уникальных сочетаний страницы, роли и ширины экрана, 9 сценариев поведения. В этих проверках нет исключений JavaScript, непредусмотренных запросов тестового сценария, горизонтального переполнения документа, кнопок внутри ссылок и неподписанных полей в проверенном DOM. Это не заменяет полный аудит доступности со скринридером или проверку реальных прав.

Скриншоты находятся в локальном `output/playwright/role-after/`. До изменений: `output/playwright/role-audit/`. Эти диагностические артефакты не предназначены для коммита.

## Непроверенное

Настоящий вход, серверная авторизация с реальными пользователями, сохранение на работающем backend, Moodle/MAX на устройствах, production build и выкладка не проверялись. Длинные производственные списки и все комбинации вложенных диалогов требуют отдельной проверки с реальными данными. Docker недоступен на момент проверки.
