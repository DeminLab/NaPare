# НаПаре: подтверждённый опыт и помощники ИИ

13 октября 2026. Это полный план развития; статус каждого этапа указан отдельно. Пользователь разрешил составить план и начать реализацию. Telegram не используется; платёжный провайдер остаётся пустым.

## Цель и позиционирование

НаПаре помогает студенту получить первый профессиональный опыт через небольшие задачи работодателей, совместить их с учёбой и собрать подтверждённое портфолио при поддержке своего вуза. Траектория: учёба → навыки → посильная задача → приёмка и отзыв → кейс → следующие задачи и работа.

Уже реализован базовый карьерный контур. Связка вуз/студент/работодатель и короткие проекты встречаются у других сервисов; преимущество необходимо доказывать удобством ежедневного использования, качеством задач и результатами пилота.

## Данные и решения

В первом проходе добавляются только редактируемое описание кейса и журнал технических обращений к ИИ. Исходные задачи/результаты/отзывы не изменяются ИИ. Бриф задания и выбранные сведения кейса отправляются лишь по отдельному действию с явным согласием и указанным получателем. Структурные поля контактов, ведомостей, расписания, ключей тестов, токенов и ссылок на результаты не выбираются для передачи. Свободный текст может содержать закрытые сведения: пользователь обязан проверить его перед согласием, а для закрытого кейса использовать ручное оформление.

Результат модели — предложение. Проверка JSON не гарантирует фактическую точность: пользователь сравнивает текст с источником. Описание автора публикуется с явной подписью отдельно от исходного принятого результата и отзыва.

## Порядок технической реализации первого прохода

1. DTO, серверный провайдер и проверяемые границы.
2. Миграция описания кейса и журнала обращений; данные сохраняются.
3. Интерфейсы предпросмотра и редактирования, отключённое состояние без модели.
4. Проверки доступа, лимитов, отказов/невалидного JSON, ручного сохранения/публикации.
5. Typecheck, lint, guards, Docker, локальный API и браузер; затем коммит/пуш.

## Подключение и границы проверки

Провайдер и модель не выбираются по умолчанию. Серверные переменные: CAREER_AI_BASE_URL (HTTPS API base), CAREER_AI_MODEL, CAREER_AI_API_KEY, CAREER_AI_PROVIDER_LABEL. Совместимый API должен поддерживать POST chat/completions и JSON object response_format; формат ответа проверяется сервером. Ключ остаётся в приватном окружении. Поддержку конкретной модели необходимо проверить после выбора провайдера.

Контракт структурированного вывода: [официальная документация](https://developers.openai.com/api/docs/guides/structured-outputs). JSON mode обеспечивает JSON, но схема и поля дополнительно проверяются приложением.

- Typecheck backend/portal, lint и repository/documentation guards PASS. Docker-сборки backend/portal прошли; миграция 1700000000018 применена после приватной резервной копии вне Git.

## Второй проход: путь новичка и совместимость с учёбой

Студент сохраняет личный бюджет времени (1–40 часов), рабочие окна, часовой пояс своего учебного расписания и включительные периоды недоступности. Планирование использует только собственную группу. Из рабочих окон исключаются прошедшее время и все пары группы, включая подгруппы; пересечения не учитываются дважды. Под активные работы консервативно резервируется весь заявленный объём: фактический прогресс не известен.

Каждая задача получает объяснение допуска, часов и срока в пределах ближайших семи дней. Нехватка времени — предупреждение; действующие условия отклика сохраняются. Если группа отсутствует, источник не вернул занятия или расписание недоступно, совместимость неизвестна. Пустое расписание не объявляется свободным временем. Оценка не учитывает дорогу и самостоятельную подготовку, не гарантирует актуальность источника и не экстраполирует нагрузку за пределы семи дней.

Работодатель указывает требования и уровень (стартовый/обычный/повышенный). Это его описание, а не автоматическая оценка профессиональной пригодности. Работодателю показываются только направление и основание утверждённого допуска по реальному профильному отклику: тест, проверка центра или неуточнённое историческое основание. Рабочие окна, пары и материалы проверки ему не передаются. Посещаемость и оценки не участвуют в подборе.

В интерфейсе следующий шаг определяется наличием профиля, проверкой центра, допусками, принятыми работами и кейсами. Не создаются вымышленные достижения или автоматический рост рейтинга.

Локальная проверка второго прохода:

- 35 backend suites / 266 tests PASS, включая интервалы, дедлайны, недоступные даты, прошедшее время, отказ расписания и запрет доступа работодателя к плану студента.
- Backend/portal TypeScript, lint, boundary guard и documentation guard PASS. Docker-сборки backend/portal прошли; миграция 1700000000019 применена после приватной резервной копии базы.
- 31 локальный API-запрос: сохранение, валидация, изоляция двух студентов, запрет работодателю, реальные локальные учебные занятия, недоступный период, уровень и требования, обратная совместимость старой формы. ИИ остаётся configured=false.
- В браузере бюджет 6 часов и стартовый черновик с требованиями сохранились после перезагрузки. Проверены следующий шаг без профиля, основание допуска в кабинете работодателя, сортировка и отсутствие переполнения на ширинах 390/685/1440. В проверенной сессии ошибок console error нет.
- Данные задач, компаний и профилей в этой проверке синтетические локальные. Production не обновлялся. Пилот, реальная генерация ИИ, автоматический рост уровней и выплаты не проверены и не объявляются реализованными.
