Подготовка на 16 октября 2026. Оператор по сведениям владельца: ИП Демин Данила Алексеевич, ИНН 550146543714, ОГРНИП 325554300088638. Публичный email и адрес для обращений ещё не предоставлены. Утверждённая дата действия, сроки хранения, получатели и фактические условия инфраструктуры неизвестны. Без них нельзя считать текст политики готовым.

Факты текущей Android-реализации для составителя политики:

- Приложение открывает HTTPS `napare.sano.ru`; серверный вход по email/паролю, роли и учебные данные принадлежат существующему веб-сервису. Android не создаёт отдельную копию аккаунта.
- В AndroidManifest объявлен только INTERNET. Нет запроса контактов, геолокации, камеры, микрофона и широкого доступа к накопителю. Файлы выбираются пользователем через системные диалоги; содержимое выбранного файла может передаваться сайту при отправке формы.
- WebView использует cookie и локальное хранилище сайта; принимает только собственный HTTPS-хост, не обходит ошибки TLS. При новом запуске основного Activity удаляются accessToken и refreshToken сайта; это не очистка всей истории обработки данных сервером.
- Локальный план: введённые пользователем дата, время, заголовок, заметка, отметка выполнения и случайный ID записи. Хранение в приватном файле приложения до удаления пользователем, удаления приложения или очистки его данных. План не привязан к аккаунту, не отправляется на сервер автоматически и остаётся доступен при смене аккаунта.
- Пользователь может сам отправить текст плана в выбранное приложение через Android Sharesheet. Получатель определяется пользователем; такая отправка отличается от автоматического сбора данных.
- Штатный cloud backup и device transfer исключены конфигурацией приложения. Общедоступная копия плана не создаётся автоматически.
- Нативных рекламных/аналитических SDK и нативной доставки push в оболочке нет. Это не утверждение об отсутствии журналирования, аналитики, обработки IP-адресов и сторонних интеграций на production-сайте.
- Подключение MAX необязательно для входа; при использовании интеграции надо отдельно раскрыть фактические передаваемые данные. Веб-карьерные ИИ-функции также требуют проверки получателей данных и отражения в документах, если доступны пользователю.

Нужно подтвердить по серверу и операционным договорам: обязательные/опциональные категории данных, образовательные записи, причины отсутствий и приложения, хранение файлов и журналов, фактические получатели, провайдеры и расположение обработки, сроки и основания хранения, процедура удаления/обезличивания и исключения для сохраняемых учебных записей. Не использовать старые обещания о работающем Firebase push или обязательном входе по телефону: они не соответствуют этой сборке.

Сейчас DELETE users/me деактивирует пользователя, не выполняя полноценное удаление/обезличивание. Нельзя писать в политике, что эти действия уже реализованы. После согласования и реализации проверить процедуру из приложения на тестовом аккаунте, затем разместить утверждённую политику по публичному URL и заполнить декларации RuStore теми же фактическими сведениями.
