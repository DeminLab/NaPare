# Аудит и модернизация НаПаре

Дата аудита — 19 ноября 2026 года. База сравнения — локальная ветка `main`, коммит `9160158`. Правки внесены в рабочее дерево поверх уже начатой установки AI DevKit. Окружение проверки использует синтетические учётные записи и отдельный PostgreSQL.

## Результат

- Студент видит окна от 30 минут, текущую и следующую пары и сроки собственных карьерных работ в «Моём дне». Из панели сроков можно открыть раздел «Мои работы». Для пары из внешнего расписания доступен переход в расписание.
- В дневном и недельном представлениях видны номер и тип недели, рассчитанные сервером по учебному календарю. Пустой календарь и ошибка загрузки показаны отдельными состояниями.
- Студент может сохранять открытые карьерные задачи своего вуза, искать внутри избранного и удалять сохранённое. Выбор хранится в PostgreSQL и учитывается до пагинации.
- В предпросмотре импорта администратор видит возможные пересечения входящих занятий по группе, преподавателю и аудитории. Пересечения определяются по времени, стык двух пар считается допустимым, отменённые строки исключаются. Для новых выгрузок можно сопоставить столбец внешнего ID, чтобы обновления находили то же занятие.

## Найденные проблемы и исправления

| Приоритет | Проблема и влияние | Исправление |
| --- | --- | --- |
| P1 | `GET /schedule/changes` возвращал студенту и преподавателю все изменения своего вуза, включая чужие группы и сотрудников. Метаданные пагинации включали чужие строки. | Студент ограничен своей группой, преподаватель — своим ID. Студент без группы получает пустой результат. Числовые группы используют свой внешний источник. Основной scope вуза проверяется до чтения. |
| P1 | Карьерный планировщик связывал дату занятия с UTC и вычитал время по строке локальных часов. Ранние пары с положительным смещением могли занять неправильный день. | Границы запроса и учебных окон рассчитаны по IANA timezone. Пересечения считаются по timestamps и обрезаются на локальных границах дня. Прямой источник СИБИТ интерпретируется как Омск независимо от часового пояса сервера. |
| P2 | В «Моём дне» внешние занятия открывали отсутствующую страницу Pair Space. Ближайшее занятие и пересечения зависели от разбора строк часов в браузере. | Статус опирается на timestamps API. У внешних строк нет перехода в Pair Space, у ближайшей внешней пары есть переход в расписание. Окна вычисляются между действующими занятиями с учётом наложений. |
| P2 | Номер учебной недели не выводился рядом с выбранной датой. | Интерфейс использует `/schedule/week-type`, обновляется по выбранной дате и показывает отдельные состояния отсутствия календаря и сбоя. |
| P2 | Фильтра «Избранное» в карьерном каталоге не было. | Добавлены `PUT/DELETE /career/tasks/:id/favorite`, `GET /career/tasks?saved=true` и массив `savedTaskIds`. Новые записи привязаны к владельцу и вузу. Повторное сохранение идемпотентно. Существующее избранное расписания сохраняет старый контракт. |
| P2 | Сроки работ приходилось проверять отдельно в карьере. | `GET /my-day` добавляет до трёх ближайших сроков работ текущего студента со статусом «В работе» или «На доработке», от текущей даты по шестой следующий день включительно. |
| P2 | Превью импорта не показывало коллизии между строками выгрузки. | Использована существующая секция предупреждений. Сопоставление группы идёт по разрешённому ID, преподавателя — по ID источника или нормализованному имени, аудитории — по тексту. Возможные совместные занятия и одноимённые помещения требуют ручной проверки. |
| P2 | Мастер CSV/JSON терял стабильный ID из файла. | На шаге сопоставления можно явно выбрать внешний ID. Пустое поле сохраняет исторический ключ файла и номера строки. |

## Оставшиеся приоритеты

1. **Расписание.** Определить единые правила календарной даты для ручных записей, импортов и экспорта. Затем проверить все представления и источники на границе суток и на переходе зимнего времени. Для ручного редактирования нужны транзакционная проверка конфликтов по ресурсам и явная модель совместных занятий и подгрупп. Для аудиторий желательно использовать стабильный ID корпуса и помещения.
2. **Карьера.** Расширить сценарий вакансий отдельным редактором резюме, профилями компаний и рекомендациями по всему каталогу. Добавить мероприятия, слоты консультаций и проверку вместимости. Уточнить политику уведомлений и метрики подтверждённого трудоустройства.
3. **UX.** Пройти оставшиеся маршруты всех ролей с проверкой сохранения и повторного открытия, ошибками сети, клавиатурой, screen reader, обеими темами и реальными устройствами. Установить baseline для Core Web Vitals, профиля NestJS и планов SQL на репрезентативных данных. Из этого этапа нет измерения утечек памяти.
4. **Безопасность и интеграции.** Проверить применимость трёх moderate advisories к runtime путям и подобрать совместимые обновления. Начать пилот 1С после согласования контракта и обезличенной выгрузки. Живые шлюзы доставки, биллинг, реестр компаний и AI-провайдер требуют отдельно настроенного тестового окружения.

## Продолжение. Вакансия и собеседование

Добавлен отдельный каталог вакансий и стажировок. Проверка центром ограничена своим вузом. Студент откликается снимком профиля, работодатель может предложить время и место встречи. При подтверждении API проверяет фактическое расписание и уже подтверждённые собеседования. Подтверждение появляется в «Моём дне». Экспорт и удаление аккаунта учитывают данные отклика.

Рабочие маршруты, правила видимости и ограничения описаны в [документации карьерного центра](docs/modules/career.md#вакансии-отклики-и-собеседования). Самостоятельный редактор резюме, рекомендации вакансий, публичные страницы компаний, консультации, доставка уведомлений и внешние календари остаются в следующем этапе.

Проверки продолжения охватили 564 unit-теста, 13 бизнес-тестов с настоящей PostgreSQL и 4 971 проверку JWT и guards. Одновременное подтверждение двух пересекающихся предложений сохранило один слот. В чистой PostgreSQL применены миграции по `0052` включительно. Прошли TypeScript, ESLint и сборка backend, Portal и Student под WSL. В Playwright три роли прошли публикацию, отправку резюме, отказ при пересечении с парой, новое предложение и подтверждение с появлением в «Моём дне». Ширины 320, 390, 768 и 1440 px не дали переполнения. Снимки находятся в `.cache/audit/vacancy-confirmed-390.png` и `.cache/audit/vacancy-my-day-390.png`.
