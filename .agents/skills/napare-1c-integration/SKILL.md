# Интеграция NaPare с 1С

## Назначение и применение

Проектировать и реализовывать явно запрошенный обмен NaPare с университетской 1С на основе согласованного контракта и существующей инфраструктуры импорта. Применяйте автоматически при соответствующей задаче; загрузите только этот навык и необходимые профильные документы. Начните с `AI_CONTEXT.md` и текущего `AGENTS.md`. Все пути ниже относительно корня репозитория; команды выполняются из корня, если не указано иное.

## Рабочий процесс

1. Сначала найдите фактический 1С connector через rg; отсутствие реализации обозначьте явно. Наличие CSV/ICS/XLSX/SIBIT/Moodle импорта не доказывает готовую 1С интеграцию.
2. Зафиксируйте конфигурацию/версию 1С и предоставленный API/выгрузку, справочники, владельца каждого поля, direction, частоту, объём и обработку удаления. Не угадывайте OData URLs или объектную модель.
3. Сопоставьте external ID со scoped organizationId справочников групп/преподавателей/занятий. Сохраните внешние идентификаторы и журнал маппинга; совпадение имени не гарантирует identity.
4. Спроектируйте adapter к существующему connector/import pipeline, schema validation, dry-run, idempotency, checkpoint, retries и отчёт imported/updated/rejected.
5. Используйте только обезличенные fixtures и отдельную тестовую БД/песочницу 1С. Проверьте дубликаты, неизвестные ссылки, кириллицу, timezone, даты разных недель и частичный отказ.
6. Документируйте контракт, ограничения, способ сверки totals, повторного запуска, rollback и ручного разбора конфликтов. Реальный обмен остаётся непроверенным без sandbox доступа.

## Правила разработки

- Не подключайтесь к рабочей 1С или студенческой БД; не переносите credentials и выгрузки с ПД в Git/MCP.
- Не меняйте действующий импорт под предполагаемую 1С схему; интеграция должна быть совместимым adapter.
- Удаления внешней стороны не означают автоматический purge учебных записей; используйте согласованную archive/deactivate политику.

## Типичные ошибки

- Идентифицировать занятие только group/day/number без даты и затереть следующую неделю.
- Повторно создать пользователей по ФИО или выставить роли по недоверенному полю выгрузки.

## Критерии качества и проверка

- [ ] Unit adapter fixtures и import-run tests; validation неизвестных/дублирующихся external IDs.
- [ ] Повтор одного пакета не дублирует данные; чужой tenant отклонён; dry-run не пишет.
- [ ] Сверка количества/ошибок и восстановление после partial failure на sandbox; production непроверен.
- [ ] Итог перечисляет изменённые файлы, подтверждённые результаты и пробелы. Source/static, build, browser, database, device, deployment и production evidence различаются.

## Пример NaPare

Выгрузка расписания 1С для двух одинаковых понедельников должна сохранять две календарные даты и использовать существующий журнал import-run для результата.

## MCP и внешние инструменты

Context7 — документация транспортной библиотеки; официальная документация предоставленной версии 1С — источник протокола. DBHub — синтетическая схема; GitHub — review контракта. Никаких запросов к боевому endpoint без отдельного разрешения. Используйте только реально доступный и настроенный инструмент. Если нужна авторизация или перезапуск клиента, завершите независимые локальные этапы и укажите точный blocker; не утверждайте, что подключение проверено. При спорной или меняющейся семантике используйте актуальный первичный источник и указывайте проверенную версию.
